# NetKit 词典的译法基准（四本词典共用这一份）

★ 为什么要有这份文件：词典是 40 个分片并行译出来的。没有基准，
「网卡」在一片里是 NIC、另一片是 network adapter、第三片是 interface ——
同一个界面上就会出现三种说法，而这种不一致是**没人会去改**的那类债。
分片译者不许自己另定译法；这里没有的词，先按「现场工程师在英文手册里实际怎么写」选，
并且把你定的那一条回报到最终消息里，由合并的人补进本表。

## 一、不许译的东西

- 工具名与判定码：`net.dhcp.leases`、`bandwidth-busy`、`rtmp-no-media` —— 原样留着
- 命令行与文件路径：`pktmon`、`/dev/bpf*`、`C:\Program Files\…`、`launchctl bootstrap`
- 标识符与占位值：`id="spwho"`、`class="hint"`、`{0}`、`%TEMP%`、`HKLM\…`
- 协议与缩写（英文本来就是行业语言）：DHCP、VLAN、RTMP、RTSP、HLS、ONVIF、GB28181、
  SNMP、PoE、MTU、TCP、UDP、RSSI、SSID、BGP、OSPF、NAT、QoS
- 品牌：昱弘网通 / Yuhox NetKit 在界面文本里极少出现，出现了就保留原文并加英文括注
- ★、〔〕这类标记符号与排版用的空白、换行、缩进：位置照原样，不许顺手美化
- 「举例的地址」：`192.168.1.20`、`203.0.113.9`、`example.com` 一字不改

## 一·b、译文里**允许**照抄的中文串（检查器认这一节）

★ 这一节是机器读的：`scripts/i18n-lib.cjs` 把本节反引号里含中文的每一条挖掉之后再判
「还留着中文」。也就是说，**只有写进这张表的东西可以以中文出现在译文里**。
为什么要有这张表：客户站点名现场就叫「金宇建安」，译成 Jinyu Jian'an 反而对不上工单；
路径 `/tmp/升级包.bin` 是程序打印出来的，改了它就找不到文件。
但例外必须是**看得见的表**，不许是判据里的松口 —— 一句「四个汉字以下算了」，
三个月后就没人记得它为什么在那儿，而整段抄过来的译文正好是四个汉字以内最多的时候。

- 品牌：`昱弘网通`（英文界面写 `Yuhox NetKit`，中日韩界面保留 `昱弘网通` 并可加括注）
- 客户/站点名（工单上的名字，不是我们的文案）：`金宇建安`
- 程序自己打印的路径与文件名：`/tmp/升级包.bin`

往这张表加东西的条件：**这个东西在四种语言的界面上都必须长得一样**。
"这个词不好译" 不是理由 —— 那是要你去想一个说法，不是要进表。

### 二·b、四本词典做完之后量出来的那一批（少数派已由 `scripts/i18n-terms.cjs` 统一）

这一节的每一格都不是设想，是**在已交付分片里数出来的多数派**：四本词典是几十个 agent
分箱并行译的，开工时拿到的基准是我转述的，而转述错过好几次（把「出口网卡」说成
`送信側アダプタ` 之外的写法、把「对端」说成 `반대편`）。转错的那一次不会有任何人看见 ——
每个分片自己都自检通过，只有整页读下来才发现同一格在两处叫两个名字。
所以这一节的另一半长在 `scripts/i18n-terms.cjs` 里当替换表跑，不靠这一张备忘。

★ ja 的「老化」这一格**不是靠多数派定的**，别照上面的方法"纠正"回去。上一轮量出来的多数派
确实是汉字「老化」，但那是 4 对 5 的差别，而整本 ja 词典里同一类词全用片假名借词
（ネイバーテーブル、マスキング、プロミスキャスモード、デュアルスタック、アプライアンス）——
只有这一个概念写成汉字，而汉字写法跟中文原文**一模一样**，正是这套尺子要防的那种歧义：
审校的人看见「老化」两秒内判不出是日文还是漏译。外部佐证拿不到（这一轮检索返回的全是中文文档，
没有日文样语可数），所以依据是**库内的语域一致性**，不是"日文圈就这么写"这种验证不了的断言。
ko 顺手收了三个名字（열화 / 수명 만료 / 노후화，6:2:1），统一到 노후화。

★ 反面的一条：**语境不同造成的两种说法不要硬统一**。ja 的散文里「向こう側」（9 处）
和术语位上的「対向」（96 处）是一回事的两种写法，读起来都通，替换表里就没有这一项 ——
把 prose 也换成术语，句子会变成机器腔，那种"一致"比不一致更难读。

## 三、句子的说法

- 界面里的短句（按钮、标签、表头）：译成**该语言界面里真正会用的那种短说法**，
  不要逐字。英文按钮用 Title Case 之外的常规大写即可；日语用「です/ます」体以外的
  UI 常体（体言止め优先）；俄语用未完成体动词原形作按钮文案。
- 长说明句（`.hint`、`★` 那几段）：这是这套产品的**判断依据**，必须完整译，
  不许压缩成摘要，也不许拆成两句加解释 —— 加解释会让中英两版的字数对不上，
  下一个人就看不出哪一句是原文。
- 「它说的那句」「原始结果」这种指的是**对端返回的原文**：译成
  "What it said" / "raw result"，指的是原文照抄的那一段，不是要你去译别人的日志。
- 中文里的「这台」「那一档」「这一问」是产品内部的说法：
  en 用 this device / this case / this check；不要直译成 that machine。
- 破折号、括号、书名号「」：换成目标语言的常规标点；`★` 保留。
- 数字与单位：`12 MiB`、`3389`、`5000 毫秒` —— 单位按语言习惯（en: ms/MB；
  ja/ko/ru 可用本地写法），数字本身一个都不许动。
