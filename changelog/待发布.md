# 技术说明
feat(tools): net.discover —— 把还没配 IP 的设备从链路上喊出来

- 起因是现场真事：新盒子插上交换机，网里没有 DHCP，**IPv4 下无解** —— 没地址就没法扫，只能扛显示器键盘一台台配
- 解法是 IPv6 天生就有的：内核给每块网卡自动配 `fe80::`，不要 DHCP、不要授权，插上网线就有。往 `ff02::1`（本链路全部节点）发 ICMPv6，所有活着的设备都会应答，**包括一个 IPv4 都没有的**
- 判定码分四种，区分的是「要不要人去干活」：`found-unconfigured` / `all-configured` / `no-responder` / `no-link-local`
  - ★ `no-link-local` 单独一种：**本机自己 IPv6 被关了、压根没喊出去**，和「网上没设备」是两回事。现场就踩过 —— macOS 那块网卡 IPv6 是 Off，`ping6 ff02::1` 直接 `No route to host`。判定里直接给出打开的命令
- ★★ **`hasIPv4: false` 必须是有证据的结论**。第一版直接拿 ARP 缓存对，真机一跑就误伤：缓存过期后 6 台地址配得好好的设备全被判成「没配网」。ARP 是缓存，**「我缓存里没有它」不是「它没有地址」的证据**
  - 改成关联前先把本网段的 IPv4 主动过一遍（`primeARP`），问了还不吭声才算数；没探过就如实给 `null`，不硬给 `false`
  - 真正起作用的是发包的**副作用**：往同网段发包内核必须先 ARP 解析，所以对方哪怕拦了 ICMP、只要还应 ARP 就能拿到 MAC，比指望它回 ping 可靠
  - 探过的网段写进结果：用户得知道这个否定结论是**在哪个范围内**成立的（它的 v4 可能在别的网段）
  - 大于 /22 自动跳过 —— 再大就不是「顺手问一遍」而是全网扫描
- ★ MAC 必须补零后再比：macOS `arp` 打 `3c:6d:66:ba:3:f7`（不补零）、`ndp` 打 `3c:6d:66:ba:03:f7`（补零）。不规整就两张表永远对不上，症状是**每台设备都被判成没配网**
- 收包方式和 `net.ping` 不同：一发多收，一个请求引来整条链路的应答，要读到超时并按源地址去重，不能收到第一个就返回
- 只收 `fe80::`：全局地址本来就有别的办法发现，混进来只会让结果变噪音。zone 一律换成**接口名**（内核有时回填的是接口索引，索引换台机器就变了，复制粘贴去 ssh 会连错网卡）
- 真机实测（192.168.3.0/24）：喊出 9 台，含一台**刚插上、完全没配 IP 的新盒子**，v4 关联 9/9 正确、误判 0。这台盒子随后就是靠 `ssh fe80::…%en7` 配上地址的，全程没接显示器键盘
- 测试 4 组，逐条钉住上面这些坑

# 技术说明
feat(tools,media): 补齐那次现场排查的只读工具（ping / 邻居表 / RTSP 分辨率）

- 工具从 2 个增到 5 个，都是 `read`：`net.interfaces`、`net.tcp.probe`、`net.ping`、`net.neighbors`、`media.rtsp.probe`
- ★ **`internal/media`：自研 SPS 解析，不依赖 ffmpeg**（docs/设计.md「流探测自研方案」）。H.264 与 H.265 都做了，纯位流解析、不解码
  - 「1088 陷阱」单独钉了测试：1080 不是 16 的整数倍、编码时补到 1088，**不减裁剪窗口就会报成 1088** —— 而那次现场排查要的就是这个数准不准
  - 必须去掉防竞争字节（00 00 03），不去的症状是**大多数流看着正常、偏偏某些分辨率算错**
  - H.265 的 profile_tier_level 里有 43 位保留字段必须按位跳，跳错一位解出来就是个"看着合理"的错数
  - ★ **先验 profile_idc 再往下解**：不验的话一段乱码也能解出 16x16 这种看着合理的结果，比直接报错坏得多（16x16 本身合法，所以不能靠尺寸判）
  - 测试向量由 **x264/x265 在已知分辨率下真实编码生成**，不是手写的。★ 我最初编了几条 base64 向量，测试直接失败 —— 编测试数据只能证明代码自洽，证明不了它认得真东西
- `media.rtsp.probe`：OPTIONS/DESCRIBE → SDP → 解 SPS 拿真实分辨率。**支持 Digest 认证**（大华、海康默认都是 Digest，只做 Basic 等于在最常见的设备上用不了）。判定码区分 stream-ok / auth-required / not-found / no-response / unreachable —— 这几个的区分就是「盒子没画面」的排查树
  - 凭据不进结果、不进日志（结果会发给 AI），单独写了测试钉住
  - 没拿到参数集时**如实说拿不到**，不编一个分辨率
- `net.ping`：ICMP/ICMPv6，优先非特权数据报套接字（不用 sudo），拿不到权限时回 `permission-required` 并**说清怎么办**。★ 判定码区分 `unreachable`（收到明确不可达 → 路是通的、终点有问题）和 `no-reply`（什么都没收到 → 分不清主机不在还是 ICMP 被拦）—— 很多工具把这两种混成"不通"，那正是现场最容易走错方向的地方
- `net.neighbors`：★ **v4 读 ARP 表、v6 读 NDP 表，是两张不同的表**，一并给出。四个平台的解析各写各的，用真实命令输出做测试样本。一族读不到不丢另一族的结果（双栈机器上 v6 读不到很常见）
- 端到端实测：AI 经 MCP 连调四步 —— 看网卡（en0 双栈 / en7 单栈）→ ping → 探 554 端口 → **探出 2560x1440 h264**。本机 ARP 10 条、NDP 18 条
- 新增依赖 `golang.org/x/net`（BSD-3，纯 Go，无许可问题），只为 ICMP
- 测试 70 条全过

feat(api,mcp): API 本体 + OTS 一致性层 + MCP 薄封装 + 前两个只读工具

- 架构按 `docs/设计.md`「AI 接口」落地：**本地 HTTP API 是唯一本体**，Electron 界面和 MCP server 都是它的客户端。这样 [OTS-4.5]「不许有只存在于 API 的能力」是**结构上的必然**，而不是一条要人记住的规矩
- `internal/ots`：把 OTS 规范里**能用代码强制的条款直接强制掉**
  - 工具不声明 read/mutate 就注册不上，且**不许默认** —— 默认成 read 正好会放行一个忘了声明的改系统工具，那是最坏的默认值
  - 工具没有说明、没有入参 schema 一律注册不上 —— 调用方（AI）只能靠它们选工具和填参数
  - **符合性类别是算出来的**（有没有暴露 mutate 工具），不是配置出来的 —— 配置出来的符合性等于自己说自己合格
- `internal/api`：HTTP API。★ 绑非回环地址却没设令牌 → **启动失败**，不是警告。警告会被忽略，启动失败不会；一个挂在 0.0.0.0 上不要令牌的运维 API 等于把改机器的能力挂在网上。`":8080"` 和 `"[::]"` 都算对外，这个容易看漏
- `internal/mcp`：MCP 薄封装，**不含任何业务逻辑**。按当前修订 **2026-07-28** 实现（2026-09-19 查证官网，协议已改为每请求经 `_meta` 协商 + 必备 `server/discover`，与知识里的老版本不同）；同时兼容 2025-11-25 及更早的 `initialize` 握手，现场客户端版本参差不齐
  - 版本不支持回 `-32022` 并**列出支持的版本**，客户端才能自己降级重试
  - 工具失败走 `isError` 结果而非 JSON-RPC 错误 —— 让模型看得见失败内容、能自己改参数重试
  - 同时给 `structuredContent` 和序列化 JSON 文本，照顾不支持结构化输出的客户端
- 工具两个，都是 `read`：`net.interfaces`、`net.tcp.probe`。★ [OTS-4.3] **发流量去观察是 read 不是 mutate** —— 归成 mutate 会导致一次 ping 都要弹框，最后大家把确认关掉
- `cmd/netkitd`：`netkitd` 起 HTTP API，`netkitd -mcp` 跑 MCP。★ MCP 模式下日志强制走 stderr —— 往 stdout 打一行就会冲坏协议流，且表现成客户端莫名其妙断开
- 端到端实测：`server/discover` → `tools/list` → `tools/call` 全通；`net.tcp.probe 127.0.0.1:9` 判定 `closed`；`net.interfaces` 在本机报出 en0 双栈（含公网 v6 前缀与带 zone 的 fe80::…%en0）、en7 仅 v4
- 测试 46 条全过。新增的 MCP 与 API 测试是**逐条钉 OTS 条款**的：停用 mutate 后 MCP 那条路也不许暴露它（否则 AI 成了后门）、端口关着是判定不是错误、认不出的错误必须归成 internal

feat: 建仓骨架 + 双栈地址地基（netaddr / netif）

- 开工第一刀。按 `docs/交接.md` §5 的顺序：建骨架 → 合并三份 netx。IPv6 从第一行代码就写进去，不设「IPv6 期」（`docs/设计.md`「IPv6 支持 · 四、写进纪律」）
- `internal/netaddr`：全项目统一的地址表示。用 `netip.Addr` 不用 `net.IP`（定长、可比较、能当 map key、自带 zone）
  - ★ `Addr.Zone`（接口名）和 `Addr.ZoneID`（接口索引）**分开存，不存拼好的字符串**：Linux/macOS 的 zone 是 `%en0`，Windows 是 `%12`。`DialString(goos)` 按平台翻译
  - ★ Windows 上拿不到接口索引时**报错而不是拿接口名硬拼** —— 硬拼出来的地址不会报错，只会 Dial 超时，是最难查的那种 bug
  - `Scope()` 分出 回环/链路本地/内网(含 v6 ULA)/公网/组播；`HostPort()` 给 v6 自动加方括号；`Parse()` 宽进（认方括号、zone、前缀的各种组合）严出
- `internal/netif`：网卡枚举。合并 argus-netx + pass-netx + relay netinfo 三份同源分叉，以 argus 版为基线
- ★★ 合并时修掉原实现**四处「v4 独大」的假设**，它们在纯 v6 / 双栈环境下会给出错误结论：
  1. `if !ipnet.IP.IsLinkLocalUnicast()` **直接丢掉 v6 链路本地地址** —— fe80:: 在 v6 上每块网卡必有，很多排障场合只能用它
  2. `IPv4/IPv6 []string` 两个字段 —— v6 丢了前缀长度、没有 zone、分不出 全局/ULA/链路本地/临时地址。改成一个 `[]netaddr.Addr`，因为「一台设备一个 IP」的数据结构本身就是错的
  3. 排序 `score()` 只看 `len(IPv4)` —— **纯 v6 网卡被排到列表最后**，而 v6-only 现场里它才是用户唯一要找的那块
  4. `len(IPv4)==0` 就说「没有拿到 IP 地址」 —— v6-only 下这是**错误诊断**。改成 v4/v6 分开给结论，且「只有 fe80::」单独给一句（网卡是好的，但 DHCP 和 RA 都没给地址）
- 本机实测：这台 Mac 的 en0 报「双栈正常，网段 2408:…:aab0::/64、192.168.2.0/23」——**那条公网 v6 网段按原实现根本不会显示**
- 测试：netaddr 11 条、netif 10 条，全过。写测试时抓到两个真 bug：`[fd00::1]/64` 剥方括号时把 `/64` 一起吃掉了；测试助手 `mk` 漏设 `Virtual` 导致排序那条白跑
- 授权：按老板 2026-09-19 决定，**产品里不做任何授权机制**，编译台只注入品牌资产

- 每块网卡下面给一句人话判断：是双栈都正常、只有一种能用、还是根本没拿到地址；没拿到地址时会说清楚是哪一步没给（路由器没发、还是要手工设固定 IP）

feat(dhcp,ui): 开启路由（DHCP 服务器）+ Electron 界面

★★ 起因（老板 2026-09-20）：「我所有设备都在交换机里，但是没有人能自动分 IP，
所以一个电脑开启 DHCP 后，能给所有设备自动分 IP。」

- `internal/dhcp`：自研 DHCPv4 服务端与探测器（RFC 2131/2132），纯 Go 无依赖
- `internal/state`：**先登记后执行、崩了能还原**的账本。所有改系统的功能都要过它
- `internal/ots`：加**人工批准闸**。[OTS-7.1] 授权只能来自人在界面上那一下点击；
  [OTS-7.3] 调用参数里写什么都不算数。★ 没有批准渠道 = 改系统的工具一律拒绝，**不是默认放行**
- 工具 7 个：`net.dhcp.probe/defaults/serve/leases/events/bind/setip/stop`
- `ui/`：Electron 界面。★ 它**只是 API 的一个客户端**，和 AI 平起平坐，不含任何业务逻辑

几处刻意的设计：

1. ★★★ **开服务之前强制先探**：网里已经有 DHCP 时再起一个，会造成地址冲突和间歇性不通，
   是最难查的一类故障。「没有人能自动分 IP」这句话必须实测，不能听说。实测中这台机器
   所在的网就探到了路由器（192.168.0.1 正在发地址），闸按预期拦住了
2. **没配网关就不下发网关**：填一个通不了的网关，设备会把它当默认路由，
   表现成「拿到地址了却什么都访问不了」，比不发难查得多
3. **默认参数自动算**（老板：「dhcp 有默认参数，可以修改」）：池子自动避开本机地址和
   网段头几个常被路由器占的地址。让人自己填，等于让他当场做三个判断，而填错的后果不是报错、是整网乱掉
4. **改 IP 靠 NAK**：DHCP 是客户端来要的协议，服务端推不动。设备下次续租时回 NAK，
   它会立刻重新 DISCOVER 并拿到新地址。★ 如实告诉用户生效时机（最长半个租期，拔插网线可立刻）
5. **新设备事件**（老板：「有设备接入能自动显示新加入的」）：租约表回答"现在有谁"，
   回答不了"刚才多了谁"。按 seq 增量取，界面高亮新接入的

测试抓到的四个真 bug（都在代码注释里留了因由）：

- `Validate` 里本机地址落在池内的判断写成了双重否定 + else，**本机地址正好等于池子起点时会放行**
- 改绑后设备重新要地址，被当成"新接入"又冒一次泡 —— 同一台设备反复"新接入"，人就不信这个提示了

**v6 看着一切正常（有地址、有默认路由）却出不了外网**：应用优先走 v6，于是每次连接先卡几秒再回落 v4，
表现成「网很慢」而不是「网不通」。查这类问题原本靠老手的一串判断，现在一个按钮：

1. v4 / v6 **分开**盘点：有没有可用地址、有没有默认路由、网关通不通、出不出得了外网、DNS 解析得到吗
2. 同一个域名的 A 与 AAAA **分别**连一次，各记耗时
3. 按 Happy Eyeballs（RFC 8305）模拟应用实际会怎么选，**直接指出会不会卡、卡多久**
4. 顶层给一个判定码（`v6-egress-broken` 就是那个招牌场景），人话由界面渲染

  - ★ 解析函数全部做成**不吃命令、只吃文本**的纯函数，三个平台的真实输出各钉一条样本测试。
    这样 Windows 的解析在 mac 上也测得到 —— 否则要有一台 Windows 机器才能验证，实际永远不会去验
- ★★ **v6「在场」不能只看有没有地址**。VPN 场景下 v6 常常只在 utun 上有默认路由、物理网卡没有全局地址，
  只认地址会把它判成「这一族不存在」。所以 `present()` = 有地址 **或** 有默认路由，通不通交给出口探测说了算
- ★ 测出口用 **TCP 连 443**，不用 ping：很多网络禁 ICMP，ping 不通不代表上不了网；
  TCP 连上了才是应用眼里的「能上网」
- ★★★ **真机第一次跑就抓到一个会让整页结论作废的错**：出口探测只能挑一个固定地址，而公司网单独把
  `1.1.1.1` 丢了 —— 于是 v4 判 `filtered`，配上 v6 也确实坏了，顶层结论成了 `both-egress-broken`（「两族都出不去」）。
  可同一个域名的 A 记录 **232ms 就连上了**，v4 明明是好的。这个误判在现场是要命的：
  会把「修 v6」引导成「查上游整个断了」
  - 改成 `reconcileEgress`：这一族的域名地址**真连上了**，就是它能出外网的直接证据，**证据优先于探测点**，
    把出口判定翻回 `open`，并把探测目标改写成实际连上的那个地址（结论里看得见证据是谁）
  - ★ 只在有证据时翻：域名也没连上就保持原来的失败判定，不硬拗成「通」；这一族压根不在场也不许被点亮
- Happy Eyeballs 的「卡」分两档给：**守 HE** 的应用约 `connDelay + v4 耗时`，**不守 HE**（串行把 v6 试到超时）
  最坏卡到 v6 超时。现场遇到「很慢」的应用时，这两档的差别决定要不要去追那个应用
- 界面「连通性」页顶部加了体检卡：结论条（红/黄/绿由判定码决定）+ 两族并排逐项 + A/AAAA 各自耗时 + HE 结论。
  ★ 码 → 人话仍然全在界面这一侧，后端只给码（多语种靠这条分工）
- 真机实测（Wi-Fi en0，192.168.1.107/24）：结论 `v6-egress-broken`。v4 出口 `open` 215ms（证据是域名 A 记录，
  1.1.1.1 那条确实被丢）；v6 只有 utun0 的 6 条默认路由、无全局地址、AAAA 两条全连不上；
  HE 判 `willStall`，守规矩约卡 465ms。改前同一台机器报的是 `both-egress-broken`
- 测试：顶层判定码 9 条、HE 决策 6 条、出口证据修正 4 组，加三个平台的路由解析样本，逐条钉住上面这些坑

feat(tools,netif,ui): net.dns.query —— 点名问一台 DNS 服务器，把「解析不对」分成三种查

★ 现场有一大类问题是「网络是好的，就是解析不对」，而「解析不对」又分三种，处理办法完全不同：
服务器压根没回（出网被拦 / 它挂了 / 配错）、它回了 SERVFAIL（它自己的上游坏了）、答案本身不对

- 判定码 `resolved / no-record / nxdomain / server-failure / refused / timeout / unreachable / bad-response`
  - ★ **NOERROR 但没有这类记录（NODATA）单独一码**：域名是有的，只是没配 AAAA / 没配 TXT，
    和「域名不存在」是两件事。把 NODATA 报成「不存在」会让人去查一个根本没写错的域名
  - ★ `timeout`（什么都没回）**不是错误**，是判定 —— [OTS-6.2]：对方不回是查出来的状态；
    只有参数不对、报文构造失败才回错误
- 支持 A / AAAA / CNAME / MX / TXT / NS / SOA / PTR / SRV。查 PTR 直接填 IP，
  ★ 反写名字（`10.1.168.192.in-addr.arpa`、v6 逐**半字节**反写）由代码算 —— 现场没人记得住规则，

- 自己发 DNS 报文（`golang.org/x/net/dns/dnsmessage`）而不是走系统解析器，为的是拿到 **rcode、TTL、答案原值**：

  - ★ **核对回包的查询 ID 和问题名字**：DNS 是无连接的 UDP 服务，收来什么就信什么，
    等于把「谁都能伪造一份应答」的门开着
  - ★ 带 EDNS0（声明能收 1232 字节）：不带的症状是多记录的域名被按 512 截断，
    **答案少了但看不出来** —— 调用方以为自己拿到了全部。仍然截断时改走 TCP 重问一次
- 新增 `netif.SystemDNSServers()`：读本机现在在问哪几台 DNS（含配它的网卡），跨三个平台
  - macOS 走 `scutil --dns`。★ **不能读 /etc/resolv.conf**：那个文件在 macOS 上不代表系统真正在用的 DNS
  - ★ 真机输出里接口名是 `if_index : 14 (en0)`（**在 nameserver 后面**、名字在括号里），
    按想象中的 `if_name` 且「先见到接口再见到服务器」来解析，一块也归属不上去 —— 这类顺序假设只有真机能纠正
  - Linux 读 /etc/resolv.conf：systemd-resolved 的 `nameserver 127.0.0.53` **如实报**，不替它展开成真实上游
    （「本机其实在问存根」本身就是排查时最关键的一条）
  - Windows 优先 `Get-DnsClientServerAddress`（结构化），拿不到再退 WMI `Win32_NetworkAdapterConfiguration`
    —— Win7 上前者不存在，而 Win7 还要单独出包
- ★ 结果里把**系统配的几台 DNS 一并报出来**（带网卡）：不指定 server 时问第一台，
  但「为什么解析到了内网地址」这种问题只有看得见全部几台才查得下去
- 界面「连通性」页加 DNS 查询卡：类型下拉、可指定服务器、答案带 TTL，每个判定码配一句下一步往哪查
- 真机实测：A / AAAA / MX / TXT / SOA / PTR 全通；指定 223.5.5.5 与系统 114 各问一遍答案一致；
  不存在的域名判 `nxdomain`；问一个不通的地址判 `timeout`（1.0s 如实回来）
- 测试：PTR 反写名字（v4 与三种 v6 写法，逐字对照权威算法）、rcode→判定码 6 条、

feat(tools,netif,ui): net.tls.check —— 证书体检，把「打不开」拆成四种完全不同的毛病

★ 「网页/设备打不开」在界面上是一句红字，实际上至少四种毛病长得一样，而处理办法互相冲突：
证书过期（必须重签）、名字和地址不一致（改访问方式或重签）、自签没进信任列表（装根证书，证书本身没坏）、
设备只支持 TLS1.0（换证书没用，要升级设备协议栈）。浏览器不会替你区分，这一页替人拆。

- 判定码 `cert-ok / cert-expired / cert-not-yet-valid / cert-name-mismatch / cert-self-signed /
  cert-unknown-authority / cert-expiring-soon / cert-weak-protocol`，加连接层的
  `not-tls / handshake-failed / no-certificate / name-unresolved / closed / filtered / unreachable`
  - ★ 一个服务常常**同时踩好几条**（过期 + 名字也不对 + 自签）。顶层只给最要紧的那一个，
    其余全部如实留在 values 里（`hostnameMatch` / `trusted` / `selfSigned` / `weakProtocol` / `reason`）
  - ★ **故意带着 `InsecureSkipVerify` 把握手跑完，再自己验、自己判**。走标准校验的话第一个失败原因
    会把后面的信息全挡住 —— 证书过期时你就看不到「其实域名也不对」，修好过期又撞上一个名字问题，白跑一趟
  - ★ 「还没到生效时间」几乎从来不是证书的错，是**设备时钟不对**（掉电重置回几年前）。判定码单独一条，
    note 直接往校时上引，不让人去换一张其实没问题的证书
- `assessTLS` 做成**纯函数**：时间、协商到的协议版本、链验证结果全从参数进来。
  ★ 顺手把链验证从里面拆出来（`chainErr` 当参数）—— 不然测试断言里混进「这台机器恰好信什么」，
  同一份测试只在某些机器上过
- ★★ **真机跑出来的第一个错：自签永远判不出来**。用了 `leaf.CheckSignatureFrom(leaf)`，
  可它顺带要求这张证书有 **CA 资格**，而现场设备的自签**叶子**证书恰恰没有 CA 标记 ——
  于是自签被报成「缺签发者那一级」，把人引去装一张根本装不进去的根证书。
  改成只看两件事：主题与签发者同一个名字，且签名能被它自己的公钥验过
- ★ **macOS 上 Go 把证书验证交给系统的 Security 框架**，回来的是一条纯文本错误（没有类型可断言），
  `errors.As(UnknownAuthorityError)` 在真机上不成立。补文本识别 —— 否则自签设备的 reason
  会变成一句英文塞在中文里。这类差异只有真机能暴露
- 域名和 IP 都吃，且**域名两族地址挨个试到握手成功为止**：只取解析结果第一个地址，
  会把「AAAA 排在前面但 v6 出不去」（本机就是这个网络环境）算成证书坏了。
  逐个结果留在 `attempts` 里，顶层码按「离证书有多近」挑（不是 TLS > 握手没谈成 > 端口关 > 丢包 > 到不了），
  并**用挑中那一条的 detail**，不拿最后一个错去解释第一个判定
- ★ **SNI 不能放 IP**（违反协议）：用 IP 访问时不发 SNI，但仍按这个 IP 核对证书里的 IP SAN，
  两件事分开。想用域名核对又只有 IP 时，填 `serverName` 就是干这个的。核对名一律用**不带 zone** 的地址，
  带 `%en0` 去 `VerifyHostname` 永远不会匹配
- `MinVersion` 放到 TLS1.0：不放的话老设备握手失败，而我们只收到一句「协议版本不支持」，
  看不出它到底能谈到哪一层；能谈下来才谈得上判断「这是不是太老了」
- `internal/netaddr` 加 `Addr.IsValid()`：调用方靠它分「拿到的是 IP 还是域名」，
  少了这个方法每处都得知道里面裹着个 `netip.Addr`，封装就白做了
- 真机实测：`expired.badssl.com` → `cert-expired`（已过期 4181 天）；`self-signed.badssl.com` →
  `cert-self-signed`（改前是 `cert-unknown-authority`）；`example.com:80` → `not-tls`，
  四个地址逐个记（两条 v4 是明文、两条 v6 是 `no route to host`）；`192.168.1.1:443` → `closed`；
  不存在的域名 → `name-unresolved`
- 界面「连通性」页加证书检查卡：结论条 + 协议/套件 + 有效期与剩余天数 + SAN 名字 + 三项核对 + 证书链 + 逐个地址。
  ★ 码 → 人话仍然在界面这一侧；**没拿到证书的判定不摆一张空证书表**
- 测试：过期压倒其他、未生效、名字不匹配优先于不受信、自签与缺中间证书分开报、
  **无 CA 标记的自签叶子证书**、SAN 里写 IP 才算数、快到期压过老 TLS、挑码与细节配对、

  绕回自己，是三种完全不同的问题。所以 `maxRedirects=0` 停在第一跳和**绕圈**必须是两个码，

  前面花掉的几百毫秒凭空蒸发，剩下的时间**全被算到「服务端自己想」头上** ——

  - 改成按整条链**累加**（`addStages`），每跳各自成功走到的那几段加进来；

feat(tools,ui): net.trace —— 路径追踪，把「上不去」查成「断在第几跳、停在哪台设备」

- 「连通性」页原来的四张卡各管一段：双栈体检答「这一族出不出得了外网」、DNS 答名字、证书答信任、

- ★ 为什么调系统命令、不自己发 TTL 递增的包：要认出**中间路由器回的那个 ICMP 超时**（这才叫得出
  「第几跳是谁」）得能读原始套接字，那要 root；非特权套接字只能知道「报错了」不知道是谁报的，
  等于没有路径。所以这里做的是**解析与判定**，不重造发包器
  - 用哪条命令如实写进结果（`engine` + 每族的 `command`）：换一台没装 traceroute 的精简 Linux，
    结论的可信度不一样，这点不许藏
- 判定码：族内 `reached / stalled / no-response / max-hops / no-route / needs-privilege /
  trace-timeout / no-command`，复用 `name-unresolved`；顶层 `path-ok / path-partial / path-broken / path-incomplete`
- ★★★ **两族并排，但「没结论」绝不能算成「断了」的证据**。第一版顶层合成把 `max-hops`（跳数用完）
  和 `no-response`（第一跳起全黑）也计入「answered」，于是 `ipv4=max-hops + ipv6=no-route` 报成
  `path-broken`，`ipv4=stalled + ipv6=没装命令` 报成 `path-broken`
  - 这三类的真实含义都是**这次没看出来**：该做的动作是把 maxHops 调大、换台机器、或改用 ping 确认终点，
    而不是去查一台根本没坏的路由器
  - 改成三堆分开数：`到了` / `确定没到`（stalled、no-route）/ `没结论`（max-hops、no-response、超时、缺命令、要权限），
    只有第二堆参与「断了」的判断；有一族压根没跑成时，顶层一律降成 `path-incomplete` ——
    报 `path-ok` 会把没测过的 v6 当成好的，报 `path-broken` 会让人去查没坏的路，两个方向都得堵
  - ★ 单族目标（只有 A 记录）不走合成：一族时直接把族内的码透上去，
    「max-hops」「no-route」这些精确码比一个含糊的顶层码有用
- ★★ macOS 的 v6 是**另一个程序**：`traceroute` 不认 `-6`（打一行用法就退出），得用 `traceroute6`。
  不区分的症状是「v6 一行跳都没有」，看着像那条路是空的，其实是命令用错 —— 真机第一次跑双栈就撞上
- **`no-response` 是这一页最容易被误读的码**：路由器不回 ICMP 超时（ICMP 被限速）时整条路都是全黑，
  而目标可能好着。所以它和「断在第 N 跳」是两个码，且界面明写「这不说明路断了」
- 中途个别跳丢包是常态，判定**只看最后一个有回应的跳往后**：`1 2 * * 4 5(=目标)` 判 `reached` 不判 stalled ——
  据「第 3、4 跳没回」说路断了会让人去查一台正常工作的骨干路由
- 三种命令的输出形状分开解析（BSD/Linux `traceroute`、Windows `tracert` 共用「跳号打头」那一套，
  `tracepath` 形不同单独一套）：
  - 地址用 `netip.ParseAddr` 认，不用正则：v6 地址带冒号、同一位置还夹着 `(host.name)`、`<1 ms`、`ms` 这些 token，
    正则很容易把 `fe80::1%en0` 切一半
  - ★ `%en0` 这类 zone 要摘掉再存：它是**本机网卡名**，每台不一样，留着会让「这一跳是不是目标」的
    字符串比对永远对不上 —— 到了终点也报没到
  - `<1 ms` 是亚毫秒不是坏数据，按 0.5 记；为了这个丢掉整跳，症状是「这一跳明明回了却显示没回」
  - `*` 记成丢了几个，不是「没有这一跳」：丢掉它就看不出断在哪
  - `!X`（禁止转发）、`!H`（禁止主机）单独留成 `mark`：那是这一跳**明确拒了**，和「没回」不是一回事
  - ★ tracepath 会把本机那一跳印两遍（`1?: [LOCALHOST] pmtu 1500` 和 `1: 192.168.1.1 …`），
    按跳号合并；不合并的话那条说明行会冒充「第一跳没回」，整族被判成 no-response
- ★★ 目标要交给外部命令当参数，所以**以 `-` 开头或中间带空白直接拒**：否则 `-f`、`--back` 会被
  traceroute 当成自己的选项吃掉（参数注入）。域名和 IP 本来都不含空白，拒掉的没有一个是正常输入
- 「本机没路」和「没权限」必须分开：`No route to host` 是**现场要的那个结论**（v6 被关的招牌表现），
  `Operation not permitted` 是工具跑不动。混成一类的代价是人去改网络设置，而真实情况只是没给权限
- ★ 超时被杀也要解析：已经走到的那几跳还在缓冲区里，扔掉等于把线索丢了 —— 带着 `partial` 回来，
  并且判成 `trace-timeout` 而不是 `max-hops`（后者会把人支使去调 maxHops，该调的是超时）
- 两族分预算（各一半，下限 3s）：不分的话 v6 卡满 60s、v4 一行结果都没有，而「v6 卡住」正是这一页要查的东西
- 界面「连通性」页新增「路径追踪」卡：逐跳画成一排方块，**丢的跳留灰块不让它从图上消失**（只画回了的那些，
  人就看不出第 3、4 跳根本没吭声），终点那格标绿；没跳时怎么说按原因分开 ——
  本机没路 / 缺命令那种不写「一个跳都没回来」（会被读成「这条路是空的」，而真实情况是压根没开始走）
- 真机实测：`192.168.1.1` 判 `path-ok`（两跳，终点标出）；`example.com` 走出 `192.168.0.1 → 192.168.1.1 → 10.45.0.1 →

# 技术说明
feat(tools,ui): net.mtr —— 逐跳持续探测，把「偶尔卡一下」查成一条有起点的丢包

- 「路径追踪」答的是「现在通不通、断在第几跳」，答不了「这条路是不是**一直**在丢」。
  现场主诉偏偏是后者：画面隔十几秒花一格、传两分钟断一下 —— 单跑一次 traceroute 全绿，
  于是有人下了「网络没问题」的结论。这一栏把同一批跳连着问几十次，就是为了拦住那次误判
- ★★ 这一栏真正的产品价值不是列出每跳丢包率，而是**判断哪一行的丢包是真的**：
  中间设备普遍对 TTL 超时的 ICMP 做限速 —— 表上是一行 100% 丢包，可它后面每一跳都收得到，
  说明被转发的流量它一个都没丢，只是自己不爱回话。只看单跳丢包率做判定，
  就会让人提单去查一台正常工作的骨干路由。所以丢包必须**看有没有一路延续到可测终点**：
  - 中段丢 + 下游收得到 → `quality-silent-loss`（不是故障，那一跳单独标「只丢自己的回应」）
  - 从某跳起一路丢到终点 → `quality-loss` 并点名起点 `lossHop`（只说「有丢包」等于让人自己再去表里找）
  - 中间全好、只有终点丢 → `quality-target-loss`（路是通的，事在终点自己：限速 / 防火墙 / 它忙不过来）
  - 往返从某跳起抬升 30ms 以上**且到终点还是慢** → `quality-latency-jump`；
    单跳慢、下一跳回到原样不算（那是那台设备的 ICMP 优先级低，不是链路慢）
- **一发不算证据**：丢包要同时满足「样本够、真丢至少两发、比例过线」。
  真机第一次跑就把一台好好的网关报成「终点在丢包」—— 8 个探测里丢了 1 个（12.5%），
  任何一条正常局域网都会偶尔这么干（第一发的 ARP、对端限速）。比例门槛单独挡不住这种噪声
- **分母不许虚高**：某一轮在第 6 跳就断了，第 7、8 跳那轮**根本没被问过**，不能记成「丢了」。
  虚高的丢包率会让人去查一条根本没走过的路。终点那一跳例外：某一轮没印出它，
  就是那一轮没走到终点，按它自己的历史补成丢若干发
- **注记之间分优先级，低的盖不住高的**：丢包类注记优先于「路径翻动」和「变慢起点」，
  同一跳既换地址又在丢时说「它在丢」（第一版反了 —— 后面的往返判定把丢包起点那行的注记覆盖掉了）
- 引擎两条路，输出汇成同一个形状，判定规矩只写一遍：装了 mtr 就用它的 `--json`
  （同样的时间里每跳样本多一个量级），没装就跑多轮 traceroute（Windows 只有这条路）
  - ★ 只给六成预算给 mtr：它要是卡住（要 root 却不回话），把整族时间吃光就一轮 traceroute 都跑不了，
    拿回 0 个样本报出来像「这条路没质量」，其实只是这一支命令没跑成
  - 形状不认识就退回多轮，绝不照着半懂不懂的字段编统计；同一跳被拆成多条时按探测数加权合并
  - ★ 诚实说明：这台机器没装 mtr，所以 mtr 那条支路是按其 JSON 报告的公开形状写的
    （单测用两份样本喂），**没有真机跑过**；多轮 traceroute 那条支路是真机跑出来的
- 两族并排时「谁坏说谁」，但**没测成的那族不算坏也不算好**：一族缺命令 → 顶层 `path-incomplete`。
  理由和「路径追踪」那一条完全相同
- 每轮分预算（剩余时间 / 剩余轮数）：不分的话第一轮就吃掉全部时间，后面几轮一行样本没有，
  而「多轮」正是这一栏存在的理由；轮数不够时如实标「不完整」
- 界面「连通性」页新增一张卡：每跳一行，丢包率画成小条**并把分母写在旁边**
  （只写 12.5%，人不知道是 8 个里丢 1 个还是 60 个里丢 10 个），
  注记那一列直接说这一行为什么算/不算故障；真丢包的行整行高亮
- 真机实测：`192.168.1.1` 判 `quality-ok`（8 个探测里丢 1 个不再报成故障）；
  `example.com` 走出「第 4 跳换过下一跳」判 `quality-path-changed`、v6 判 `no-route`；
  浏览器里逐跳表、假丢包、真丢包带起点、只有终点丢、一族没命令五种形状逐个点过
- 测试：丢包真伪判定表（含一发不算、样本太少不给结论）、拥塞点点名、往返抬升延续到终点才算、

  加权合并、顶层合成（没测成的那族不参与「坏」）、命令按族选、目标写法（注入拒收）。全绿

# 技术说明
feat(tools,ui): net.time.check —— 问一台权威时间源「现在几点」，把「是谁不对」和「差了多少」分开答

- 起因是这类排查一律绕远路：证书报「还没生效 / 已过期」、日志时间戳排不成序、DHCP 租约被算成早就到期 ——
  现场照着症状查证书、查网络，半小时之后才发现那台设备掉过电，时钟停在几年前。
  该先问的是「现在几点，谁说的」，这一栏就是把这句话做成一个按钮
- ★★ 「差了多少」和「是谁不对」是两件事，这一栏不许把它们混成一句：
  只问到一个时间源时，那 3 年既可能是本机错、也可能是对方错 —— 拿单方说法指认本机就是编。
  所以默认问多个源，结果里单独给 `attribution`：`none`（没问到）/ `single-source`（只问到一个，**只报偏差不指认**）/
  `corroborated`（多个源自相一致，才说本机不对）/ `conflict`（源之间对不上，说明有个源自己就是坏的）
- ★ 偏差的符号按 NTP 口径：**正 = 本机落后**（要往前调）。第一版写成了「正 = 本机快」，
  方向反了等于把结论说反 —— 这条现在有测试钉着，并且界面上永远写成「本机慢 / 本机快」而不是一个正负号
- 一次问答就是标准的 θ/δ：θ = ((t1−t0)+(t2−t3))/2、δ = (t3−t0)−(t2−t1)。三个实现上的坑：
  - **取往返最短的那次**，不是图快：一次被队列拖了 200ms 的问答，会把「本机落后 3 毫秒」算成「落后 100 多毫秒」
  - **认回包**：NTP 没有事务 ID 可依赖，能核对的只有回包里的 OriginTimestamp（我们发出去时盖的那个戳）。
    对不上就不算这次的答案 —— 不然链路上任何一个漂着的 NTP 包都能被当成答复用掉
  - **往返算成负数直接拒**：那是服务器自己的钟在跳（未同步的源会这样），
    不能把它当成「往返 0 毫秒的高置信样本」用掉。同理服务器时间戳全零的、mode 不对的、短包，一律判 `time-bad-response`
- ★★ 一个源「没答」有四种原因，必须分开，因为处理办法完全不同：
  - `name-unresolved` 域名解析不出来 —— 连着的是 DNS，不是防火墙。混进「没回」会让人去查一条根本没挡着的防火墙
  - `time-no-response` 一个包都没回 —— 才是 UDP 123 被挡（很多出口默认不放）
  - `time-kiss-rejected` 对方明说不给：`RATE` 是问太密被限速，`STEP` 是它直说你的钟偏过了它的容错 ——
    **后者本身就已经替本机确诊了**。KoDR 从 stratum 0 的参考时钟字段里取，做成**类型化的错误**带码返回，
    不靠从错误文本里捞（改了措辞就把结论改没了）
  - `time-bad-response` 回了，但不是 NTP：端口上挂着别的服务，或者链路上有东西在改写 NTP
- 只读判定里留着「这个时间源是谁」：stratum、它自报的上游、它的时钟读数、问了几发回了几发。
  「服务器说几点 / 本机说几点」必须成对给 —— 只给一个毫秒数，现场看不出那是差一分钟还是差一秒
- 闰秒预警（LI=1/2）不当错误、也不丢掉：那是「接下来一天里对时会有 1 秒台阶」的现场信号
- 各源**并行**问（串行问三个源、每个三发，最坏要 9 秒才看到第一行结果），但**先按地址去重**：
  并行问同一个地址两次，第二次大概率吃一个自己造成的 `RATE` 拒答 —— 那是这一栏自己造出来的假结论
- 阈值：2 秒以内算正常（网络往返本身就有几十毫秒），超过 2 分钟算「大到会让证书和租约出错」
  （TLS/Kerberos 的容错、租约判断就在这个量级上），源与源之间差过 2 秒算「有源自己不准」
- 真机实测：默认两个公网源都答了，判 `time-ok`、偏差 50 毫秒、两源互差 2.9 毫秒。
  ★ 有个现场发现值得记：两个公网源自报了**同一个上游** `10.191.8.4`（一个内网地址）——
  说明这网络上有东西在代答 NTP。把「它的上游」原样列出来就是为了这种事看得见，而不是让人去猜
- 测试：用一个进程内的假 UDP 时间源把时间戳全部握在手里（打公网源只能验形状，验不了「差 500 毫秒」是不是 500 毫秒），
  逐条钉住符号方向、θ/δ 的确切数值、取最短往返、负往返与漂着的回包被拒、四种「没答」分开、
  顶层判定十例（含「解析和没回混着时不许只报解析」）、源之间矛盾时不指认本机、区号要先去掉、
  重复源要去掉、没答的源也要留一行。另有一条真打公网源的冒烟测试，不在网上就跳过

# 技术说明
feat(tools,ui): net.udp.probe —— 探一个 UDP 端口，把「没人回」这三种病分开

- UDP 没有连接这件事，所以「发一发没回」同时兼容三种完全不同的现场：**端口没人监听**、
  **端口开着但它不答你这句话**、**整条路径把 UDP 丢了**。前两种要查对端，第三种要查中间设备，
  合成一句「不通」等于把方向交回给人猜 —— 这个工具的主要工作就是把它们拆开
- 四个判定码：`udp-responsive`（有回包，唯一能确定的好结果）、`udp-closed`（收到 ICMP 端口不可达：
  主机在、这个端口没服务）、`udp-silent-alive`（目标不出声但**对照端口**出声，能排除「整机不对」）、
  `udp-silent`（两个都不出声，这条路对 UDP 静默，连机器在不在都不知道）
- ★ **对照探测是这个工具的价值所在**：再打一个肯定没人监听的端口，只取它「出不出声」，
  不判它开没开。出声就把结论从「机器不在」降级成「这个端口自己的事」；不出声才敢说 UDP 整段被丢。
  生产设备上不想往没点名的端口发包可以 `noControl` 关掉（只多发一个包，但它确实不在用户点名的范围里）
- `closed` 只能来自连好的 UDP 套接字：不 connect 就收不到 ICMP 差错（那要 raw socket、要管理员权限），
  connect 之后 read 才会把 ECONNREFUSED/ECONNRESET 顶上来。**代价一并写进注释**：它同时按源端口过滤回包，
  服务从别的端口回你，这里就当没收到 —— 宁可不判，也不误判成 closed
- 只发一发会把 `closed` 读成「没反应」：不少平台上 ICMP 差错要在下一次收发才浮出来，
  所以超时前补一发。★ 两发的读截止点对到**同一个绝对时间**，各等各的会把总耗时写成两倍
- **空包是真的发得出去**（Go 在连好的 UDP 套接字上确实下发零长数据报），所以不填 `payload`
  不是「什么都没干」，这一条钉进了测试。但多数服务不认识空包 —— 判不出「开着」，
  所以 Summary 直接写明：要探 SIP/ONVIF 就填协议里真实的一句话，二进制协议用 `payloadHex`
- 包根本没发出去（地址写法对但发不出去）不算静默：记 `sent: false` 并回 `unknown` 带上已有证据。
  [OTS-6.2] 的界线：**观测没做成**不是「端口不通」，把它判成任何一种判定码都是凭空造结论
- 和 `net.tcp.probe`、`net.ping` 一样只收 IP。报错要说「域名先用 `net.dns.query` 查出地址再来」，
  光说「看不懂地址」会被当成自己写法不对，而不是「这一层压根不接受域名」
- ★ 备注不许说没做过的观测：`noControl` 时不能写「对照端口也没出声」，得写「这次没跑对照，
  所以这两种分不开」—— 否则人会把一个没测过的东西当成测过的证据
- 踩到的流程问题：schema 里写成了 Go 的字符串拼接（`` `..." + itoa(x) + "...` `` 在 raw string 里就是字面量），
  JSON 因此非法，`MustRegister` 在**启动时**才 panic。单跑 `internal/tools` 抓不到，
  是 `internal/api`、`internal/mcp` 那两组真的注册了一遍才炸出来 —— 提交前跑全套，别只跑自己那个包
- 真机实测：本机起两个 UDP 端口（一个回包一个收到不答），四种判定各自跑通 ——
  responsive 记回包 4 字节、silent-alive 带着「对照端口 23456 出声了」、
  closed 走的是刚释放的端口（内核真回了 ICMP 不可达）、silent 的备注如实写了「没跑对照」
- 测试 14 条：空包发得出去、十六进制报文按字节到对面、十六进制写错直接拒、对照组把两种静默分开、
  关对照就一个额外包都不发、对照端口等于目标端口不跑、closed 与「没反应」分开、只收 IP 并指路 DNS、
  没回话写成人话（「等了 200ms 没回话」而不是 Go 的 `i/o timeout`）、取消要立刻收摊不等满超时

# 技术说明
feat(tools,ui): net.ports.scan —— 一次问一台主机一片端口，把「全关着」和「一个都没回话」分开答

- `net.tcp.probe` 问一个端口，这一栏问一片。区别不在数量，在**扫完之后能不能给出一个整体结论**：
  现场真正要的那句话不是「22 关着、80 关着、554 关着…」，而是「这台机器活着、只是这些端口没服务」
  或者「连机器在不在都不知道」—— 两句话的下一步完全相反
- 顶层四个判定码：`ports-open`（有端口连上）、`ports-closed`（一个没开，但有端口回了拒绝 → **主机是活的**）、
  `ports-no-response`（一个回执都没有）、`ports-no-route`（包根本没出去，查自己不是查对端）
- ★★ **只要有任意一个端口回了 RST，就不许报成「没回话」**。九个被丢、一个拒绝，那一个拒绝就足够
  证明主机在、路也通；报成 `ports-no-response` 会让人去查一条根本没挡着的防火墙，
  或者干脆认定设备坏了。这条单独钉了测试（`scanCodeFor` 做成纯函数，九例逐个锁）
- ★ 「没路」必须和「被丢」分开，且**不能从「全被丢」里凑出来**：`no route to host` 是本机连一条路都没有
  （一个包都没发出去），`i/o timeout` 是发出去了没人答。前者要查自己的网卡和路由，后者才轮到对端防火墙。
  errno 各平台不统一（Linux `ENETUNREACH`、macOS 常给 `EHOSTUNREACH`、Windows 是 WSA 那条，
  而且有的包装层不透出 errno），所以 errno 和文本两边都认
- ★ **逐端口明细只在端口不算多时给**（超过 200 条就省掉，只留汇总和 `openPorts`，并置 `portsOmitted`）。
  结果是要发给 AI 的、也可能进诊断包：两千条 `closed` 里没有一条是信息，
  但足以把真开着的几个端口埋掉。省明细不许省结论 —— `openPorts` 永远完整
- ★ **并发池的意义不是快，是有界**：不控并发扫两千个端口就是瞬间造两千个套接字，
  本机端口和文件描述符先耗尽，症状是「扫到后面全都判不出来」。固定 worker 数（默认 32、上限 128），
  测试用「保留地址必然等满超时」把耗时变成证据：12 个端口、并发 4、每个 250ms → 三批，
  不限并发会是一次 250ms，串行走要 3s
- ★ 单次上限 2048 个端口，不是性能考虑而是**别让人把这一栏当扫描器使**；扫过 64 个就在结果里带
  `warning: many-connections`。这不是客套：不少摄像头和录像机把短时间内的批量连接当成爆破，
  直接把这个来源 IP 锁几分钟 —— 扫完发现「突然什么都不通了」，先想到这个
- `parsePortList` 宽进严出：单个、逗号、区间、混着写都认，但空片段、缺半边、反过来的区间、越界、
  服务名一律直接报错。★ **不许悄悄跳过几个端口**：少扫两个的后果是结果里写着「没有」，
  而人会把「没有」当成「这台机器上没这个服务」
- 单端口状态沿用 `net.tcp.probe` 的 `open/closed/filtered`（界面和体检项因此只有一套词），另加
  `no-route` 和 `error`。一个端口判不出来不是错误：它带着自己的状态和 detail 留在结果里（[OTS-6.2]）
- 和 `net.udp.probe` 共用「这是域名不是 IP」的判定，报错统一指路 `net.dns.query`；
  批量扫 UDP 明确不做 —— 没连接、没回执，扫一片只收获一堆「没反应」，什么都判不出来
- 取消要看住：`ctx` 取消时在 `DialContext` **外面**先拦一道。Go 的 net 包会把取消改写成
  `poll.ErrCancelled`，`errors.Is(ctx.Err())` 那条路认不出来，结果是取消了还要等满超时
- 真机实测（这台 Mac 回环）：默认集扫出 631 / 1883 / 5432 三个真开着的端口；
  `1-300` 判 `ports-closed`（300 个全回拒绝、明细按预期省掉、带 warning）；
  `240.0.0.1` 两个端口判 `ports-no-response`（备注指去 ping）；域名拒收并指路 DNS；`100-50` 拒收
- 界面「连通性」页新增「扫一片端口」：汇总一行（扫了多少 / 开着 / 关着 / 没回话 / 没路）+
  开着的端口单独列在最上面 + 逐端口表（省掉明细时把那一段话写清楚，不留一片空白），
  四个顶层判定各配一句下一步往哪查
- 测试 15 组：端口写法与坏写法、默认集内容与排序、顶层判定九例、真扫三种形状、
  明细取舍、并发有界、取消立刻收摊、没路与被丢分开、只收 IP、备注里端口列长了会折叠

# 技术说明
feat(tools,ui): net.mtu.path —— 路径 MTU，把「大包过不去」的归属判出来再给数

- 查的病是**「小包什么都好，大包过不去」**：TCP 连得上、页面打得开、登录也进去了，可视频一出来就卡住、
  传文件传到一半断 —— 路上某个环节能过的尺寸比 1500 小（隧道、PPPoE、VPN、被偷偷改了 MTU 的交换机口、
  云上的虚拟化开销）。ping 和端口探测查不出这个，**因为它们发的包本来就不大**
- ★★ 做法上唯一要紧的一点：「过大被挡」这个信号从哪来。自己发 ICMP 并去读「需要分片但不许分片」那个差错，
  要原始套接字、要管理员权限。这里换一条不要权限的路：给一个连好的 UDP 套接字设**「不许分片」**，
  二分地发 progressively 大的数据报 —— 内核会把「太长了」原样顶回来（EMSGSIZE），
  不管是本机网卡装不下还是路上设备报了 ICMP；反过来收到 ECONNREFUSED（ICMP 端口不可达）
  就是**这个尺寸完整走了一个来回**的证据。所以默认打在 9253 这种肯定没人监听的高端口上
- ★★ **归属必须算出来，不许猜**：EMSGSIZE 有两条来源，报反了的后果不是报错、
  是人照着设一个错的网卡 MTU。`mtuBlockedBy` 拿出口网卡的 MTU 去对：
  被挡的那个尺寸**超过本机 MTU** → 包根本没出过本机，只能判 `mtu-local`（要查本机设置）；
  **还没到本机上限**就被挡 → 只能是路上某台设备卡的，判 `mtu-path` 并给「照着设」的建议值；
  读不到本机 MTU → 数照样给，但**不给建议值**，并在判定里说清「分不清是谁卡的、先去看 net.interfaces」
- 出口网卡和它的 MTU 是**问内核**问出来的：连一个 UDP 套接字（不发包）看它挑了哪个源地址，
  再拿这个地址去网卡清单里对（比地址本身、不带 zone，zone 两边写法不一样带上就永远对不上）。
  自己解析路由表要每个平台写一套，而且内核挑的那块才是真的
- ★★★ **不在编译期假设「不许分片」真的生效**：探第一个尺寸之前，先发一个明显超过本机网卡 MTU 的包自查。
  被内核当场拒 = 选项真的在干活（`dfVerified: true`）；反倒发得出去 = 内核自己把大包切开了，
  接下来量到的数会偏到没有上限 —— 一律判 `mtu-df-unsupported` 并说清是这台机器测不了。
  **真机第一跑就撞上这一档**：拿本机自己那个局域网地址当目标时，包走本地投递，超 MTU 也发得出去，
  于是被判成「测不了」而不是给出一个假的 1500。这一条之所以不靠 build tag 保证，
  是因为 Windows 那条路没在真机验过（Go 会不会真的回调 Control、非管理员能不能设上都不确定）
- ★★ 「大包没回执」单独一档 `mtu-no-response`：它和「大包被挡」**长得一模一样，含义完全不同** ——
  对方不回 ICMP 差错时什么都测不出来，报成「路径 MTU 就是 N」会让人照着把网卡 MTU 设小。
  二分**中途**开始断信也一样：只说「测到这儿测不动了」，不许把已经过的那个尺寸端成路径 MTU
- 二分而不是从 500 一路试上去：一千个尺寸逐个试要发一千个包，这在现场不是慢，
  **是把自己变成攻击流量** —— 摄像头的防爆破会把这台机器锁掉，交换机也可能直接限速
- 上限没人填时用出口网卡的 MTU；填了且没撞到墙，判 `mtu-no-limit-found`：
  结论只到「至少这么大」，并指出去把 maxSize 调大再测一次（多花的只是几次二分）
- ★ 结果里的尺寸一律是 **IP 包总长**，不是载荷长度 —— MTU 本来就是按 IP 包算的，
  按载荷报会把每个数都说大 28/48 字节，人拿去设网卡就设错了
- IPv6 上测出比 1280 还小（RFC 8200 规定的链路下限）时标 `below-ipv6-min`：这不是正常的路径 MTU，
  是中间有设备不守规矩
- 逐步记录 `steps` 全程留在结果里（尺寸 / 结果 / 耗时 / 原文）：这一栏给的是一个**推出来的数**，
  人看不到「哪一步开始过不去」就没法信它
- 「不许分片」按平台分四个文件：Linux `IP_MTU_DISCOVER=IP_PMTUDISC_DO`（v6 走 `IPV6_MTU_DISCOVER`）、
  macOS/BSD `IP_DONTFRAG` / `IPV6_DONTFRAG`、Windows `IP_DONT_FRAGMENT=7` / `IPV6_DONTFRAG=14`、
  其余平台如实回「这一层没有对得上的选项，测不了」——**不许退化成「允许分片」去发**，
  那样量出来的 MTU 会大得离谱且全程没人报错。选项号是从 x/sys 的生成表和 ws2ipdef.h 核对的，不是凭印象写的
- 真机实测（macOS）：`127.0.0.1` / `::1` → `dfVerified: true`、`mtu-no-limit-found`
  （16784 字节被内核当场拒，`lo0 MTU 16384`）；路由器 `192.168.0.1` 不回 UDP 差错 →
  `mtu-no-response` 不给任何数；`240.0.0.1`（保留段）同上；本机局域网地址 → `mtu-df-unsupported`。
  工具从 27 个到 28 个
- 测试 22 组：二分步数有界（不许线性试上去）、中途断信不许端出 MTU、归属四种情况（含「正好等于本机 MTU」
  那一档）、尺寸口径换算闭合、上限是填的、v6 下限、参数校验、域名指路 DNS、取消立刻收摊、
  每一步留痕、工具声明（read + 六个判定码都在说明里）

- `internal/tools/subnet.go`：`net.subnet.scan`（ClassRead，`hosts-found` / `no-hosts`）——
  问「这个网段上现在有谁」。★ v4 下这件事**没有一个万能办法**，所以四条路子并起来，
  并且每台都带着凭什么被判在线（`evidence`: `icmp` / `arp` / `arp-cache` / `tcp`）：
  ① 先看本机 ARP 表（一个包都不发）② 主动发一轮 ICMP（真正值钱的副作用是内核得先做 ARP 解析）
  ③ 再看一遍表，捞那些「应了 ARP 但拦了 ping」的 ④ 可选 TCP 兜底（只在扫**路由过来**的网段时才有意义）
- ★★ 修掉一个只有真机扫自己网段才会暴露的 bug：**ARP 表里「解析失败」的占位条目被当成设备在场**。
  一轮 ICMP 把整段 254 个地址都塞成了 `<incomplete>`（Linux 是 `FAILED`），那些行没有 MAC，
  意思是「我问了，它没应」——结果第一次现场跑就报「253 台在线」，一张全是鬼的清单。
  现在 `neighborsByAddr` 只留**解析出 MAC** 的那几条，并且存进去就规整（补零 + 小写：
  macOS 的 `arp` 打 `3c:6d:66:ba:3:f7`，不规整同一台设备能有两种写法）。
  这条纪律写进了工具的 Summary：调用方（AI）也得知道 `arp` 这一档凭什么算数
- 「网络地址和广播地址都不问」是硬规矩：前者不是主机地址，后者会引来整段设备一起答，
  那张表就没法读了，而且最容易被人当成攻击流量
- ★ 超过 `maxHosts` 时**直接拒**，不许悄悄只扫前 N 个：没列出来的那些会被读成「不在」，
  那是凭空造的结论。`cidr` 不写前缀长度也拒（猜 /24 还是 /8 会差几个数量级，
  而症状是「扫出来的人比实际少」，现场看不出来）；掩码长过 /30 指去 `net.ping`；v6 指去 `net.discover`
- 不填 `cidr` 时扫哪些段由 `localV4Subnets` 决定：没插线的、只有 169.254 的、虚拟网卡、回环，
  一律排除并且**逐条说出为什么**（`skippedIface`）——扫这些只会得到一片空结果，
  而空结果会被读成「这个网段没人」。`onLink` 单独判：扫的是不是本机真的连着的那一段，
  这决定了 ARP 这条证据能不能用，也决定了「一个都没问到」那句说明往哪个方向指
- 自己的地址不进清单（`skippedSelf` 里说明）：问自己必然有回执，列出来每台机器都会多一行莫名其妙的设备
- `icmpSweep` 一个套接字跑完一轮：★ 认回执**只按源地址，不按 ICMP ID**（非特权数据报 ICMP
  套接字上内核会自己改写 ID，拿 ID 去对就会把别人的应答算成自己的）；每发 16 个包歇 2ms，
  否则交换机和主机的 ICMP 栈直接丢，症状是「明明在线却扫不到」而且从结果上看不出是发太快；
  收的时候每 100ms 醒一次看有没有被取消（不用「另开协程关套接字」那招 —— macOS 上关完 Read
  返回的是 "use of closed network connection" 而不是超时，会把「取消」错分类成别的结论）
- TCP 兜底并发有界（32，理由同 `net.ports.scan`），而且**只补还没信号的地址**：
  ICMP 回执比「端口有应答」硬，一律覆盖会把硬证据改写成弱证据
- 界面新增「扫描与发现」页：`net.subnet.scan` + `net.discover` + `net.neighbors`。
  ★ 后两个之前一直只有 API 没有按钮，不合 [OTS-4.5]，这次一并补上。
  三张卡的说明刻意写着各自的可信度差别（缓存 ≠ 当场问过 ≠ 只听得到应 v6 的），
  免得三样被读成一张清单；邻居表的状态字母按平台翻译（`R`/`S`/`REACHABLE`/`STALE`/`动态`/`静态`），

# 技术说明
feat(tools,ui): net.ping.watch —— 按时间连发，把「有时候卡一下」查成有名字的哪一发

- 起因是现场的原话：「有时候卡一下」。`net.ping` 四发问不出这个毛病 —— 四发全通，因为那一下没赶上。
  所以这一栏按间隔连发，把**每一发**都留在结果里（`seq / atMs / rttMs / kind`）
- ★★ 产出不是那张曲线，是**「第 9 发 · 2.4s · 264ms」**。人拿时刻去对现场发生了什么
  （是不是刚好起流、刚好有人插拔网线）；只给一条线加一句「抖动偏大」等于没答
- 判定六档，档与档之间是**处理方向**不同，不是严重程度不同：
  `stable` / `jitter`（没丢但抖）/ `loss`（丢了，★ 丢要查链路质量、抖多半是排队）/
  `no-reply`（一个都没回，连主机在不在都不知道）/ `unreachable`（每发都是明确的不可达，路是通的）/
  `no-route`（包根本没出去，查自己这边）
- ★ `unreachable` 的门槛是「**每一发**都明确不可达」：掺进没吭声的那几发就不算 ——
  不能因为有一个人回话就声称整条路是通的。有回执时不可达数照样单列（`unreachable`），
  note 里写「其中 N 发是明确的不可达，不是超时」，因为「路由时不时指不到这台」和「偶发丢包」不是一件事
- ★★ 挑尖峰拿**中位数**当基线，不拿平均值：一次 2000ms 的卡顿会把平均值抬到三百多，
  之后 300ms 那一发就「不算尖峰」了 —— 而它恰恰是用户要问的那一下。抖动按**发的先后**算，
  排序后算会偏小；分位数用最近秩不插值（要的是「第 95 分位那一发实际多少毫秒」，
  一个算出来的小数会被当成实测值抄进工单）
- ★★ `sweep` 排下一发用**绝对时刻**（`start + (seq-1)×interval`），不是「发完再睡一个间隔」：
  后者会把每一发的耗时累进间隔，越往后越慢，曲线自己长出一条斜线 —— 那是工具的睡法，不是网络的。
  测试里让假探测每发睡 12ms，验的就是「第 N 发仍落在 (N-1)×间隔 附近」
- 一整个 watch 只开一个 ICMP 套接字（每发重开的话，慢的是建套接字，曲线被自己污染）；
  回执只按 Seq 认、不按 ID 认（非特权数据报套接字下内核会改写 ID，这条是 `net.ping` 早就踩过的）
- ★ **要的间隔不等于跑得起来的间隔**：每一发都等满 `timeoutMs` 时，发序会被自己的超时拖稀。
  所以给 `spanMs / actualIntervalMs`，稀到 1.5 倍以上就在话里点明「这条曲线的时间轴不是等距的」——
  只有两点的曲线在图上看着像「这两秒都稳」，真相是这两秒里每一发都没回
- `baseline` 对照组（一般是网关）：`neither / target-only / baseline-only / both` 四档，纯算术不猜。
  ★ 两边都不干净时**不跨量纲比大小**（「丢 5%」和「抖 40ms」硬换算会得出「丢包的那边更稳」这种话），
  所以判成 `both` 之后另给一个 `compareWorse`：同一种病直接比数，各有一种病时按现场处理顺序排（丢包先于抖动）
- 护栏：`intervalMs` 不低于 200（再小就是洪泛，而且无线链路自己就会抖）、最长 60 秒
  （要长跑留痕的是「持续质量监测」不是这一栏）、间隔配时长发不到 4 发**当场拒**（看不出抖不抖）
- 真机实测（macOS）：路由器 3 秒 10 发 → `jitter`，点名第 9 发（2.4s 时 264ms）；带
  `baseline=127.0.0.1` 同轮跑 → `target-only`（对照组中位 0.09ms、抖动 0.07ms，两条线的数并排给）；
  `127.0.0.1` → `stable`；`240.0.0.1` → `no-reply` 并说明「实际每发 1001ms，比要的 250ms 稀」。
  工具从 29 个到 30 个
- 界面（「连通性」页新增「连续 ping（看抖不抖）」）：目标与对照**各画一张图**，不做双轴 ——
  把 0.05ms 的对照和 90ms 的目标塞进同一根轴，对照那条会成一条贴底的直线，
  看着像「它稳得像根线」，其实只是被刻度压扁了。★ 丢的那几发在图上**断线**并在轴底留红方格，
  连过去就是把「没回执」画成「一直很好」；抖的那一发套金环，下面单独列出「第 9 发 · 2.4s · 264ms」；
  「丢在哪几发」按三种来路分开标（没回执 / 明确不可达 / 包没出去），因为三件事查的方向不同
- ★ 踩到两个自己的坑：一是新卡片的 `#wv / #wgo / #wout` 和同页「校时检查」卡片重了 id
  （同一份文档里两个同名 id），改成 `pw*` 前缀；二是界面自己拼对照组的字段名时忘了首字母大写
  （后端 `mergeStats` 用 `upper1`），**拼错不报错**，只会让对照组八格全显示「没测到」——
  所以把这条口径写在了函数注释里，而不是等下次再撞

  取消立刻收摊且已发的留痕、实际发序被超时拖稀要讲明、丢包率与不可达分开统计、

  尖峰拿中位数当基线（含平均值会漏掉哪一发）、样本太少不挑尖峰、尖峰只列前几条、

- **「丢包」和「抖动」是分开的两种结论**，因为处理方向不一样：丢要查链路本身（信号、网线、

  这三种在别的工具里常常被合并成「超时」，而它们的下一步完全不同
- **可以填一个对照地址**（建议填网关）：同一轮里两条线各测一份，用来分「只有这台慢」和
  「这一整段都在抖」。两边都不干净时不会硬说谁更差，只会写清楚各自的丢包率和抖动，
  再按「丢包比抖动更该先查」点一个方向
- ★ 测不出来的时候不含糊：一个回执都没收到，就直说这一栏给不出稳定性结论（分不出主机不在还是挡了包）；
  每一发都拿到「到不了」的回执，就说明路其实是通的、问题在终点或路由。
  想要的时间间隔被每一发的等待拖稀时，也会写明这条曲线的时间轴不是等距的，别照着它读节奏
- 不需要管理员权限，IPv4 和 IPv6 都能测；中途点停也会把已经发过的那几秒留在结果里

feat(tools,ui): net.checkup —— 八项按排查顺序过一遍，顶层只说第一个坏掉的是哪一步

- 起因是「网络正常」这四个字最没用：`net.interfaces`、`net.ping`、`net.dns.query`、`net.dualstack.check`

  而排错方向的成本比测一遍高得多 —— 网关在丢包时，DNS 和出口测到的「慢」全是链路带出来的
- ★★ 所以这一栏的产品是**顺序**，不是八个结果：`iface → route → gateway → dns → egress → mtu → clock → proxy`
  依次判，顶层只给一个码（`all-good` / `degraded` / `broken-at-{iface,route,gateway,dns,egress,clock}`）
  加「第一个坏掉的步骤名」。八项的明细照旧全给，但界面把「先修这一步」只贴在顶层点名的那一行 ——
  八行全涂成红等于没给出顺序
- ★ 三条界线是反复推敲过的，钉死在测试里：
  - **网关不回 ping 只算 warn**。现场太多路由器默认拦 ICMP，报成故障会让人去翻一台没坏的设备
  - **「问不到」一律 skip，不许拖成 bad**：内网封 UDP/123、代理在 Windows/Linux 没有统一读法，
    这些都是常态。健康机器必须真能跑到 `all-good` —— 跑不到，这栏就废了
  - **v4 / v6 永远分开给**，不许塌成一句「网络正常」：有 v6 地址和路由却出不了外网，
    应用会先卡在 v6 上再回落，现场读起来是「网很慢」而不是「网不通」，最容易查错方向
- 出口按「TCP 真连上了 443」判，不看 ICMP（拦 ping 却照常出网的设备太常见），并且和域名那条连接路径
  互相印证后才下结论；MTU 只判物理口（隧道口 1400/1280 是本来就该那样）；代理**只给 host:port**，
  `user:pass@` 一律剥掉 —— 结果会原样发给 AI、以后还要进诊断包
- 复用而非重写：`probeEgress` / `markDNS` / `reconcileEgress`（双栈体检）和 `icmpWatcher` / `statsOf`

  整条 rollup（顺序、warn/bad/skip 分档、谁背锅）于是在不弄坏真机器的情况下被测得到
- ★ 一个数据竞态是被 `-race` 抓出来的，不是想出来的：`familyResult` 由 `probeEgress` **原地写**，

  正确的修法是让「解析→连接」在同一条 goroutine 里串起来、只往带缓冲 channel 交一次结果，

- ★★ 真机第一跑暴露三个坑，**三个都是工具自己造成的**，测试一个也没抓到：
  1. 到网关那轮按「时间窗」发、单发又等满 `timeoutMs`：链路一慢就只问到 1~4 发，

     局域网那一轮另给 500ms 单发上限 —— 六发串起来 3 秒而不是 12 秒
  2. v6 默认路由是 `fe80::%utun0`（VPN 口），拿它当网关去问 → 报 `no-reply` warn，
     等于把一副 VPN 指控成故障。改成**隧道口整条腿不问**（`tunnel` / skip），并补了「挂 VPN 体检」的集成测试
  3. 时钟明明问到了（`answered`、偏 112ms）却报成 `not-asked` —— 分支在匹配源的判定码，
     码名对不上就全落默认支。改成**只看偏差量级分档**，阈值和 `net.time.check` 共用同一份常量：
     两个工具对「差多少算事」给出两个答案，人不知道信哪个

# 技术说明
feat(tools,ui): net.port.process —— 问「这个端口被谁占了」，把要不要动手的那条线画出来

- 别的工具只能从外面问「连不连得上」，连不上却有三种完全不同的原因，**处置互相冲突**：
  本机没在听（去起服务）/ 有进程在听（要停它）/ **根本没人占，那是本机自己刚连出去留下的口**（停它就掐断会话）。
  最后这种最坑：看到 554「上有东西」就把服务停了，停掉的正是自己那条客户端连接
- ★★ 所以顶层判定不按「有 / 没有」分，按**要不要动手**分：`occupied` / `outbound-only` / `free` / `partial`，
  另给 `listening`（不填端口=列全部）/ `no-listener` / `unsupported`。七个码各带一句下一步
- ★ `partial` 这一档是整个工具的存在理由：**看不全的时候说「没人用」**，人就走去起服务，
  撞上「地址已在使用」再回头骂工具。非管理员读不到别人进程的句柄，这时只许说「只读到一部分」
- 三个平台各写各的读法，解析全部单独一层、**用真实命令输出当测试样本**（自己编的样本只能证明代码自洽）：
  - macOS `lsof -F`：不用默认那张表 —— COMMAND 列本身能含空格（`Google Chrome`），按空白切列就串位，
    症状是进程名和 PID 对不上。真机跑出来的第二个坑：`-F` 不带 `t` 字段时，v4 和 v6 的两条监听
    解出来**一模一样**，界面显示成「同一个进程被列了两遍」。加上 `t` 才有 `tcp4` / `tcp6`
  - Linux `/proc/net/{tcp,tcp6,udp,udp6}`：不依赖 `ss` / `netstat`（精简系统上没有）；
    地址是**小端十六进制**，不反字节就把 127.0.0.1 解成别的数；表头那行的 inode 列写着 `inode`、
    转数字是 0，不跳过的话「谁都没占」的记录会被归到 inode 0 上 —— 看不出来，只会偶发
  - Windows `netstat -ano` + `tasklist`：UDP 那几行**没有状态列**，按下标取 PID 会把 `*:*` 当成 PID，
    一律从行尾取；`LISTENING` 必须规整成 `listen`，不规整就是**把在听的服务报成 free**；
    地址族要在把 `0.0.0.0` / `[::]` 收成 `*` **之前**判，收完两族就分不出来了；
    `tasklist` 只取 PID 和名字、**跳过用户名列**（中文 Windows 控制台是 GBK，那一列最容易带中文）
- ★★ 真机第一跑又抓出两个只有跑起来才看得见的：
  1. `/proc/net/udp` 里一个**绑好在等包**的 socket 状态列写 07（close）。照原样交给判定层，
     跑着的 DNS / NTP / 流媒体服务会被说成「本机连出去占的口，别去停它」—— 和事实正好相反。
     改成 UDP 只保留 `established`（真被 connect 过才有意义），其余一律清空表示「绑在这个口上」
  2. 内核里的 TIME_WAIT **没有 inode**（本来就没主人）。旧写法把它算成「认不出主人」，
     于是这台机器永远 `partial`、永远说不出 `free` —— 而 `free` 恰恰是「这个口能腾出来」的答案
- 不填端口时本机轻松上百条（实测 201 个套接字、55 个监听）。这份结果整份发给 AI，所以行数设顶 120，
  截断如实标 `truncated` + `listenerCount`；没绑口的套接字（`*:*` / 端口 0）不进列表 ——
  UDP 没有状态位，留着会显示成「某进程在听 0 号端口」，本机十几条，把真在听的淹了
- ★★ **只给进程名和 PID，不给命令行**。命令行里常有口令、token、数据库连接串，而结果会原样发给 AI、
  以后还要进诊断包。Linux 侧因此**只读 `/proc/<pid>/comm`、不读 `cmdline`**；
  单独一条测试钉死字段集，以后谁想加 cmdline 得先改测试并想清楚泄漏面
- 归属动作是个可注入的 `portRead`（测试里换成固定输出），判定链因此在不碰真机器的情况下全测得到
- 界面：「连通性」页紧跟「ping / 探端口」之后 —— 从外面问不通，下一步就是回本机问谁占着。
  ★ 读不到的时候一行计数都不给：那会儿任何「在听 0 个端口」都是假结论
- 工具从 31 个到 32 个。测试 30 组：判定分档、三个平台的真实输出解析、凭据面字段集各钉一批。
  ★ Windows / Linux 这两条目前是**编译 + 真样本解析**测过的，还没在真机上跑过（本机只有 macOS）

feat(tools,ui): net.subnet.calc —— 算一个网段，把「这个输入值不值得信」放在答案前面

- 子网计算看着谁都会算，现场错的恰恰是这一步，而且**错的输入会被当成对的抄进设备**：
  `255.0.255.0` 这种不连续的掩码当合法值收下、把 `192.168.1.100/24` 里的 `.100` 当网段地址登记、
  以及最难查的 —— 新配的段和已在线上的段**重叠**，表现是「有时候连得上有时候连不上」，
  谁都不会往掩码上想。所以顶层判定不是「算出来了」，是**这个输入能不能信**
- ★★ 判定码按「要不要有人去改配置」分，不按「算没算出来」分：
  `v4-network` / `v4-host-address` / `v4-broadcast-address` / `single-address` / `v6-prefix` /
  `networks-overlap` / `families-differ`。其中只有 `networks-overlap` 是必须有人去动的结论，
  另外几种都是「数算对了、但登记时会拿错哪一格」
- ★★ **掩码不连续当场拒，不硬算**。`255.0.0.255` 的 1 不连续，缺的不是中间那一段：
  硬按最像的 /8 算，会得到一个「看着合理」的假网段，而假网段会一路配进设备。
  报错文案把二进制形态打出来（`11111111.00000000.00000000.11111111`），人一眼看得出缺在哪
- ★ **`/31` 和 `/32` 是两套规矩，按公式减二会算出「可用 0 个」**：
  RFC 3021 的 /31 互联口两个地址都能配给设备，**没有**「减掉网络地址和广播地址」这一步；
  /32 一个地址自成一段，也**没有**广播地址。这两条各钉了测试 —— 第一版就是按 `size-2` 写的，
  界面立刻显示出「可用主机数 0」和「广播地址：它自己」
- ★★ 裸地址不猜掩码。`192.168.1.100` 补成 /32 并如实标 `prefixAssum`，
  文案明说「掩码没填上，所以按一个地址算 —— 没替你猜一个 /24」。
  顺手猜个 /24 是这个工具最容易被要求做、也最不该做的事：猜出来的段会被当成事实登记
- ★ **v4 和 v6 不共用一套字段**：v6 没有广播地址、没有「总数减二」，一个 /64 就有
  1.8×10¹⁹ 个地址 —— 拿「能扫多少个」问 v6 是问错了问题。所以 v6 只给前缀、地址数和性质
  （ula / link-local / multicast / loopback / global），并单独给「这个 /48 能切出多少个 /64」。
  界面那一栏**只列后端真给了的字段**，否则就出现「广播地址：undefined」
- ★ **作用域后缀必须先剥掉**。`fe80::1%en7` 在 `netip` 眼里是「带 zone 的地址」，
  组前缀时它**不报错**，只是整栏答案变成 `0.0.0.0` —— 一个静默的错数，
  比崩溃坏得多。单独一条测试钉住：剥完必须还能算出真段
- 地址数用 `math/big`：/64 是 1.8e19，`uint64` 勉强够、/48 就溢了。
  溢出的症状是「总数是个看着合理的负数」，测试里用 v6 大段钉住
- ★ 对照段（`peer`）只回答一件事：**撞不撞**。三族关系给全：`identical` / `peer-inside` /
  `peer-contains`，另算出重叠多少个地址。CIDR 段在数学上只会「嵌套或不相交」，**不存在部分交叠**，
  所以没有 `partial` 这一档 —— 留一个永远进不去的分支，等于给以后的人留一个「以为测过」的坑
- ★ 跨族问的是「问题本身不成立」，不是「不重叠」。`192.168.1.0/24` 和 `fd00::/64`
  返回 `families-differ` 并把话说明白：各自编址谈不上撞，**真要问「这台机器两族是不是都通」，
  用 net.dualstack.check**。答成 `不重叠` 会让人以为做过一次跨族比对

# 技术说明
feat(tools,ui): net.mac.analyze —— 问一个 MAC 的来路，先答「它能不能当设备身份」

- 「MAC 查厂商」看着就是查个名字，现场真正卡人的是**拿错了地址当身份**。四条岔路各自需要不同处置：
  全零（设备没烧 MAC / 驱动没读上来）、组播（压根不是一台设备）、本机管理位被置（软件造的地址）、
  真厂商地址。所以顶层判定按**能不能当身份**分档，不按「认不认识厂商」分 ——
  认不出厂商名不影响它是个好身份；反过来认出 `02:42:` 是 Docker，恰恰说明它**不是**硬件身份
- ★★ **厂商名默认不报，而且这不是省事**：IEEE 的 OUI 注册表是 **CC BY-NC-SA**（非商业许可），
  本项目要商用分发，那张表**不许打进安装包**，抄几条进来同样是复制受许可保护的内容。
  处置办法不是砍功能，是把来源分成三层，每一层各自标清出处：
  - `protocol`：协议规定的组播 / 保留地址（`01:00:5e` IGMP、`33:33` NDP/MLD、`01:80:c2` STP、
    `01:00:0c:cc` CDP）—— 事实来自公开 RFC 与 802 标准，出处写标准号，判定标 `whoBasis: standard`（**是事实**）
  - `convention`：软件自己的默认地址段（QEMU `52:54:00`、Docker `02:42`、VMware `00:0c:29` / `00:50:56`、
    Xen `00:16:3e`、Hyper-V `00:15:5d`）—— 出处是那个软件自己的行为，标 `whoBasis: guess`，
    界面归到「推测」，人话里必须带「属推测」三个字
  - `registry`：厂商名。只可能来自**操作者自己下载的表**（环境变量 `NETKIT_OUI_FILE` 指过去）
- ★ 走环境变量而不是入参：入参等于让任何调 API 的一方（包括 AI）去读本机任意文件，
  而这张表是部署时定一次的事，不该出现在每次调用里
- ★★ **`vendorWhy` 不许留空**：没挂表时不是一句「查不到」了事，要写清「为什么这里没有名字」
  （许可不允许）+「怎么才能有」（下载 + 挂环境变量）。否则人和 AI 都会判成「这个工具坏了 / 库不全」，
  然后去换工具 —— 而换谁都一样，那张表就是不给商用
- ★ 按 24 位前缀查就有撞名的一天：IEEE 另有 32 / 40 位前缀的 **MA-M / MA-S**，
  它们的前 3 字节可能和别家重复。所以表里命中一律写「多半是这家」，不写「确定」，
  测试专门钉住这条措辞
- ★ 表去重按「同前缀只认第一条」：IEEE 的文件里每个厂商出现两遍（一条 `(hex)`、一条 `(base 16)`），
  后一条不是更正，是重复 —— 覆盖成后一条等于随机挑一个名字当事实
- ★★ 位这两栏（`group` / `administered`）**必须分开给**，不许并成一个「类型」：
  `02:…` 是本机管理 + 单播（Docker、手机私有地址），`01:…` 是全局 + 组播（协议地址），
  两者毫无关系。并成一栏就会有人以为「组播 = 随机地址」
- ★ 写法要宽（`:`、`-`、`.`、连写、大小写、带引号都得能粘进来），但**混用分隔符直接拒**：
  从 `arp -a`、交换机 CLI、设备标签抄下来的地址各是一个格式，混写通常意味着两行粘成了一行，
  接着算就是查错设备
- 把 IP 粘成 MAC 是高频错，报错点名「这是 IPv4 地址的写法」，不只说「不是十六进制」
- ★ **派生的东西宁可不给也不给假的**：EUI-64 接口标识只对单播地址给（`33:33:…` 推出来那串
  看着像真的，会让人拿它去对 NDP 表）；从后四字节反推 IPv4 只认 `02:42`（别的软件也用本机管理段，
  照着推会推出一个像真的假地址）
- 按 RFC 4291 推接口标识是**取反**那一位，不是置 1：802 地址该位是 0、v6 侧要求是 1，
  从本机管理的 MAC 推时会反过来变 0 —— 测试钉住这个方向，否则容易被"顺手修正"成置位
- 顺手给出前 3 字节 / 后 3 字节切分：两台设备「MAC 很像」时要说的是像在哪半截 ——
  前段相同只是同厂商，后段也相同才要查克隆或地址冲突
- 界面：「小工具」页第二张卡。★ 全零 / 全一那两档**不再显示「发给谁 / 地址哪来的」**，
  改成一行「这不是任何设备的地址」：位是位，但把「单播、全球唯一」摆在一个全零地址下面，
  人就又把它当设备去查厂商了
- 工具从 33 个到 34 个。测试 30 组：写法、位、四条岔路、派生、表解析与措辞各钉一批。
  ★ 这个工具是纯解析，不发包、不碰系统，四个平台的差异只在编译期

feat(tools,ui): net.mac.random —— 生成随机 / 克隆 MAC，把「凑错六个字节」的两种病当场处理掉

- ★★ **随机源必须是 `crypto/rand`，这一条写在注释里防「顺手换」**：`math/rand` 不显式播种时
  每次进程启动的序列是一样的 —— 两台机器同时用这个功能就会配出**同一个** MAC，

- 第一个字节是特意凑的：`buf[0] = buf[0]&0xFC | 0x02`（清组播位、置本机管理位，其余 6 位随机）。
  少处理任何一位，症状都不指向 MAC —— 没清组播位是「配得上、发得出去、收不到回包」，

# 技术说明
feat(tools,ui): net.codec.convert —— Base64 / URL / 十六进制 编解码，先答「解出来这东西能不能用」

- ★★ 「解一段 base64」有四条会把人带偏的路，而多数工具把它们压成同一句「解码失败」：
  - **解出来是二进制** —— 数据完好，是它本来就不该当文本读（加密 / 压缩过的字节）。
    报成失败，人就换工具、或者去查设备坏没坏，两种都不是结论
  - **老设备固件里的中文是 GBK** —— 既不是合法 UTF-8 也不是随机数据。
    并到「二进制」里说，人就去查网卡和固件；单独点出来才是可执行的一句话
  - **字母表和填充** —— 现在发出来的 token 绝大多数是 URL 安全且不带 `=` 的。
    只认标准解码器的话这类输入一律报「非法字符」，人顺着这句话去查复制粘贴，一查一下午
  - **一段串同时是好几种编码** —— 32 个十六进制字符既是合法 hex 也是合法 base64，
    两种读法出来的字节毫无关系。替人挑一个就是替他猜，猜错了他还拿那个结果去对设备
- ★ 所以顶层判定按**结果能不能直接拿去用**分七档（解出文本 / 解出二进制 / 还剩一层编码 /
  几种读法都成立 / 没在编码 / 这种解不开 / 编好了），不按「认出的是哪种编码」分
- ★★ **歧义那一档把每种读法的结果全摆出来**，最多加一句「多半是这种」和理由：
  只给一份结果的工具，人就会拿那份结果去对设备；给两份，人自己看得出哪份讲得通。
  理由只允许是「这几种里只有一种解得出可读文本」这种**结果本身给的证据」，
  不许是「我觉得这像 MD5」—— 那种话留在注释里，不写进结论
- ★★ `normalized` 是**对外承诺做过什么让步**：补填充、认 URL 安全字母表、去掉折行、去 0x 前缀，
  一条条列出来。不列就等于悄悄改了数据 —— 从网址里抄的 base64，那个空格原本可能是个 `+`，
  照着「原样解出来的」结果去对配置就对不上。
  ★ 实机验证抓到一条**假承诺**：输入明明带着 `=` 填充，却因为实现按「去掉填充后的长度」判断
  而报成「补上了缺失的填充符」。让步记错和漏记一样坏，测试专门钉住「本来带填充的不许认成我们补的」
- ★ **URL 里的 `+` 两种读法分开给**（查询串里是空格、路径里是加号本身）：
  密码里带 `+`、从地址栏抄下来贴进配置，解出来差一个字符，症状是「密码明明是对的却登不上」。
  这不是能替人选的，因为两种读法对应两个不同的密码
- ★ `4n+1` 这种长度**单独说破**「base64 每 4 个字符出 3 个字节，这种长度不可能出现」：
  它跟字符合不合法无关，报「非法字符」就是浪费人时间 —— 真相是「它不是 base64」
- ★ 两种字母表混在一段里（既有 `+/` 又有 `-_`）**不按 base64 读**，也不报错，
  而是说清「标准字母表和 URL 安全字母表不会同时出现在一个值里，多半是两段值粘成了一行」
- ★ **合法 UTF-8 和「可打印」是两件事**：只看 `utf8.Valid` 会把一坨控制字符（它们合法！）
  当作文本给人。三档分开判，二进制的结果里就不给 `text` 字段 —— 界面只列后端真给了的
- ★ GBK 那一档**只说像、不解码**：项目不引字符表依赖，而硬解出来的中文是猜的，
  猜出来的中文比乱码更容易被当成事实
- ★ 签名令牌（`eyJ…` 三段）认出并把头部和载荷分开解出来，但 **★ 只解码不验签**，
  这句话必须在结论里：不然「解得开」会被读成「这枚令牌有效」。
  载荷常带账号和内部 IP，所以顺带提醒别整段贴进工单
- ★★ **Note 里不许复述解出来的内容**：那可能是设备密码或 token，而 Note 会进日志、会发给 AI。
  内容只在 `values` 里（那是调用方自己贴进来的，他要的就是这个），Note 只写结论和长度。
  测试钉住「Note 里不许出现解出的内容」
- ★ 正向编码时，输入是明文就把五种写法一次给全：贴进来一段明文的人十有八九是要编出去，
  少一轮来回，也不逼着人猜这工具能做什么
- ★ `\u` 按 UTF-16 算，**代理对两个合起来才是一个字**：只解单个 `\uXXXX` 的话，
  emoji 和生僻字会解成两个孤立代理字符，人看到的就是「设备名字里凭空多出两个方块」。
  编码方向同理出代理对。Windows 路径不当转义串（`C:\newfolder` 里的 `\n` 是真字符）
- 工具从 35 个到 36 个。测试 41 组，五种岔路各钉一批：字母表、填充、折行、混字母表、
  `4n+1`、`+` 的两种读法、双重编码、二进制、GBK、代理对、路径、令牌、边界与 Note 脱敏。
  ★ 纯字符串运算，不发包、不开套接字、不碰文件系统，四个平台的差异只在编译期
- 界面：「小工具」页第四张卡。★ 实机验证另外抓到三处措辞会把结论说反，已修：
  解不开那一档的 `encoding` 是**你指的读法**、不是「认出的写法」；明文那一档的长度是
  **这段多少字节**、不是「解出多少字节」；输入框清空后判定药丸会留着上一次的。
  另外界面话术里不许出现字段名（原本写成「换个 encoding 再判一次」，改成「换一种读法」）
- ★★ 提交后用全新上下文复查了一轮，抓到几处真错，最伤的一类是**显示一份、编的是另一份**：
  明文带着引号贴进来时，界面显示清理过的原文 `hello world!`，下面给的五种写法却是拿
  **没清理的那一份**（连引号和尾空格）编的 —— 两个结果看着都对，人贴走的却是他嘴上说不要的值。
  现在自动档编的就是清理过的那一份，去过什么照常列进让步里
- ★ **写了 `=` 就按它自己声明的填充式验一遍**：填充个数和长度对不上，只有一种解释 ——
  抄漏或多带了一个字符。这种串换到别处（浏览器、`base64 -d`）照样解得开，解回来是个错值，
  而现场症状是「密码不对」，没人怀疑到自己抄的那一行动上，所以这里拦下说破。
  ★ 两个方向分开钉测试：`QQ=` 要说「该配 2 个」（漏抄），`AAAA=` 要说「该配 0 个」（多带尾巴）——
  只断言「认出了这类错」，方向说反也算通过，而那恰好最害人
- ★ 行中间的空格**只在「剔掉它解得出人话」时才当 base64 读**（从 PDF / 表格里粘出来那种）。
  凑出来是二进制、而原文自己就读得通（`  hello world  `），那讲得通的就是文本 ——
  以前这种判「解出来是二进制」，等于把一段好端端的文本报成坏数据。★ 折行的走另一条：
  证书和密钥本来就是折行的 base64 二进制，解出来当然不是文本，不能一起砍。
  并且把「我试过 base64、是这样排除的」写进为什么，不然人只看到一句「没认出编码」
- ★ **文本里恰好带 `%XX` 不算第二层编码**：以前看见转义就判「还套一层」，人照着再解一次，
  就把 `rate = 50%0D and %41` 这种句子解出控制字符出来。改成按「除了转义还剩不剩词」判 ——
  宁可漏判（剩下的转义符号人自己看得见）也不误判
- ★ 指死字母表分两种情况：串里真出现了 `+` 或 `_`，指错要拦（那种字符会被当成别的字）；
  两种字符都没出现时两派解出的字节一模一样，指谁都一样 —— 以前一律拒绝，
  等于把**解得开的输入**报成坏数据，而人看到的下一步是去查那枚 token
- ★ `\u` 编码要把**反斜杠自己编掉**：不编的话 `C:\new` 编出去还是 `C:\new`，再解回来撞在
  「认不出的转义开头」上，这一档在 Windows 路径上就是编得出去解不回来。
  盘符那条守卫跟着收窄一格：只在还剩一个「不是转义」的反斜杠时才当路径拦，
  否则我们自己的输出自己也读不回来
- ★ 输入上限**按字符算**（原来数的是字节却写「字符」：3000 个中文字报错说 9000 字符，
  既拦早了也说假数）
- ★ **指错写法是调用方说错了，不是「这段用那种写法解不开」**：decode / encode 两条路一律当场报错。
  以前 decode 把它做成一个判定，AI 会以为换一种编码再试就有结果
- ★ 界面：歧义那一档以前只列「读法 / 解出来」，后端在每份结果里给的**这一种放宽过什么**没显示 ——
  不显示就是少一层可核对的证据。补一列
- ★ 测试：`Test每个判定都有人话` 原本只断言「码没打错字」（恒真，什么都没钉住），
  改成真去读界面的判定文案表 —— 少一个码，客户界面上就是一个裸的 `not-decodable`
- ★ 复查第一轮报回来 6 条，其中 4 条在当前代码里**根本不存在**（它读的是改动前的副本）。

# 技术说明
feat(tools,ui): net.wol —— 发一枚魔术帧唤醒一台设备，把「按了没反应」拆成三种病

- ★★ 这是本项目第一个**对外发东西的 mutate 工具**，也是「改动只能由人点一下批准」这条闸
  （docs/设计.md 原则 2、OTS-7.1）第一次真正过一遍全流程：批准说明说什么、账怎么记、
  崩在中间怎么办，以前都只在 DHCP 那类改本机的功能上验过
  - **为什么发一个 UDP 包算 mutate**：发出去的帧**改变的是别人的状态**（让一台关着的机器开机）。
    探测类工具发包只是「看」，这一枚是「动」。判成 read 的话，它就绕过了整条批准闸
  - **批准说明只写一台设备**：`Describe` 里点名 MAC、网卡怎么选上的、发到哪个地址、连发几枚。
    ★ 口令**永远不进这句话** —— 批准框会进日志，而它下面就是那台设备的开机口令
  - ★ **先把账落到盘上再动手**（OTS-7.5）：`journal.Register` 成功才发第一枚。反过来
    （发成功了再记账），崩溃窗口里这笔改动就是无账可查的
  - ★★ 但一次性动作**不能挂着账**：`Outstanding()` 把 pending / applied 都当成「还在生效」报给
    下次启动的还原流程，而 `RestoreOnStart` 只认 `dhcp-server` —— 唤醒的账会变成一个还原流程
    去认领的、根本不存在的改动。所以发完当场 `MarkReverted` 了结，**留痕照旧在账本里**：
    什么时候给哪台发过、从哪块网卡发出去的，这些是要能回看的
- **现场「按了没反应」其实是三种病**，所以判定按这三种分，不是一句「已发送」：
  - **抄错 MAC**（MAC 打错一位、看的是无线网卡地址、快速启动后 MAC 都换了）
  - **发错地方**（从默认路由那块网卡发出去了，而目标在另一段）
  - **发出去 ≠ 醒了**（固件没开、待机没供电、跨网段那一发被路由器丢掉）
  ★ 第三种是本工具承认自己无能为力的那一档：只能把「从这块网卡到了这个地址」说实，
  然后让人回邻居表看它有没有回来 —— 说成「已唤醒」就是在编
- ★★ **绝不用 `255.255.255.255`**：那一枚会按默认路由选出口，用户点了 en0 实际从别处发出去。
  改成取**所选网卡自己那个网段的定向广播地址**（`lastAddr(prefix)`），
  并且是在发送前按网卡现算，不缓存 —— 多网卡工控机上这是唯一说得通的发法
- **网卡怎么选，四档，每档都要报出来**（`ifaceFrom`）：指定 → 邻居表里学到过这个 MAC 的那块 →
  IPv4 默认路由那块 → 全场只有一块非虚拟且有可用 v4 的网卡。
  ★ 最后这档必须**只有一块才敢自动选**：两块就列候选让人指，猜错网卡的 WoL 症状是「发了，没反应」，
  和真的没醒一模一样，白花十分钟
- **/31、/32 直接拒**（RFC 3021 那两条没有广播地址这一步）：往这种前缀上算「定向广播」
  会算出一个单播地址，帧发到别人家里去，而界面上一切正常
- ★ **「它此刻在邻居表里」不能判成「已经醒了」**，只能判「刚才大概率醒着」：ARP 条目在设备睡下后
  还要留几分钟。所以这一档**一枚都不发**、并把本来会从哪块网卡发到哪一整套行程说全
  （不发也要说 —— 人要知道下一次 force 会干什么）
  - 静态 / PERMANENT / FAILED / incomplete 这些条目**证明不了任何事**，一律不算「见过」。
    测试里专门钉：邻居表里那条 EUI-64 的 v6 条目也不许当成同一台设备
- ★ 目标地址筛掉四类：全零（设备没交出地址）、全一（那是「对全楼喊」的无差别开机）、
  组播位置着（`33:33`、`01:00:5e` —— 不是设备地址）、以及**自己的网卡 MAC**
  （唤醒自己：要么没反应要么把自己重启，而人完全看不出为什么）
- ★★ **SecureOn 口令的纪律**：结果、Note、账本、批准说明、错误信息里都不许出现口令内容。
  校验时**不复述**（每一处报错只说「口令写法不对」不说它是什么）；只接受 6 字节，
  或 4 字节且后两位是 `00 00`（不少实现按 4 字节口令比较）。
  界面上口令框 type=password，★ 而且**发起后立刻清空** —— 不然它就一直躺在输入框里
- 帧内容原样吐出来（`frame`，不带口令的那一枚的十六进制）：现场常见的是拿别人的工具对拍，
  对得上就排除「发得不对」，往下一种病查
- ★ 测试**不发任何网络包**：把发送口抽成一个变量（`wolDispatch`）在测试里换掉，
  记账那条路另用真的临时账本验（一笔、kind、What 含 MAC、status 是 reverted、
  `Outstanding()` 归零、全账里搜不到口令）。真实发送路径在本地临时环境单独验
- 工具从 36 个到 37 个。跨平台靠的是**普通 UDP 套接字**：Go 标准库在 linux / bsd / windows 上
  给 UDP 监听套接字都置了 `SO_BROADCAST`（对着 `$GOROOT/src/net/sockopt_*.go` 逐平台看过），
  所以不要求管理员权限、不引 Npcap，安装包照旧零专有依赖

  - macOS：`netstat -rn` 会打印**两棵路由树**（network + host），不去重就是一半行重复；
    v4 网段**省略主机位**（`192.168.1` 是 /24、`10.0` 是 /16），不归一成 CIDR 上层就得再猜一遍；

    结果**默认路由整批读漏**（`UGcIg` 里的 `g` 不在白名单里），是在真机上跑出来才发现的
  - Linux：主表可能是**错的**（策略路由 `ip rule` 给每块网卡挂一张表），所以「问系统」
    以 `ip route get` 为准；`unreachable` / `blackhole` / `prohibit` 是**答案不是解析失败**
  - Windows：`RouteMetric` 要和 `Get-NetIPInterface` 的 `InterfaceMetric` **相加**才是可比度量；

    `NextHop` 是 `0.0.0.0` / `::` 表示「没有下一跳」而不是网关地址；`route print` 输出本地化，不用
  - 三平台归一：目的地址一律 CIDR、`direct` 单独成栏、读不到度量就是 0
- ★ **只在 Flags 带 `G` 时才填下一跳**：BSD/Linux 的直连路由那几列里第一个字段是**本机地址**，
  照位置取就会把 127.0.0.1 报成「网关」—— 假网关比没网关更害人
- **「算出来的」和「系统自己选的」分开，不一致单独出一档**（`route-mismatch`）：
  按表做最长前缀匹配是我们的推算，各平台都有我们看不见的东西（策略路由、多张表、内核里的 host 路由）。
  ★ 这一档**两个答案都留着**、以系统的为准，而不是偷偷只报一个 ——
  「这台机器的路由不能靠看表判断」本身就是诊断结论
- ★★ **目的地是本机自己的地址时单独出一档**（`route-local`）：实机踩到的 —— 问本机网卡上的地址，
  表里给 en0、系统给 lo0，按对拍逻辑就会报成「你有策略路由」。那是**正确行为**（BSD/Linux 都把自己
  收回环），这么报等于把人推去查路由策略。反过来这一档有用：他以为的「那台设备」其实就是这台机器，
  现场最常见的是 **IP 撞了**，而这时候「能 ping 通」恰恰是假象
- ★ **并列不许假装挑一条**：macOS 的表不带度量，多条同前缀时**没有可比依据**。
  报 `route-found` 的同时把「还有 N 条同样匹配」写进结论（`ties`），
  不然「两条默认路由打架」这种真故障就被一句笃定的出口盖过去了
- **只列表时也把默认路由抽出来单看**（`multi-default-route`）：同族两条以上默认路由是多网卡机器上
  最要命的一类配置，埋在几十行表里等于没有。★ 界面上紧接着提醒「多出来的都挂在
  utun / ppp / tun 这类隧道口的话，那是 VPN 在收路线，一般不算故障」——
  不写这句，这个红标会把人吓去找网管
- **「这一族没启用」和「有这一族但盖不住这个地址」分开**（同为 `no-route`，看 `familyRoutes`）：
  前者该去开这一族，后者才去加路由 —— 混成一句，人就会对着防火墙查半天
- ★ **读不到表绝不报成「没有路由」**（`table-unreadable`）：这一族的命令不在、被系统挡住、
  平台还没实现，都会给空结果。把它说成「这台机器没有路由」是**把工具故障说成故障定位**。
  macOS 上 `route get` 甚至会在明明有 `::/0` 的时候回一句「not in table」——
  所以问系统这一步失败时，出口退回按表算，并在结论里写清是哪一种
- **一个名字解出多个地址、走的路不一样**时出 `route-split`，把每个地址各自的出口列出来：
  双栈域名、轮询解析就是这样。★ 这不是配置错误，替人挑一个才是错
- 结果**按系统选路的优先级排序**（先族、再前缀长度从长到短、最后度量）：
  默认路由排在最前面会让人以为出口就是它，而它常常被一条 /24 压住。
  解不出前缀的行沉到底部但**不丢** —— 少一行表内容比给一个错的排序好，可一行都不该悄悄丢
- ★ 表里高亮「就是这一条」那一行：按表算的能精确到行；从系统拿到的答案没有对应表行
  （它把你问的地址回显成 /32），只能按网卡 + 下一跳指回去，★ 指不准（多于一条）就一行都不标 ——
  标十行等于说「这十行都是答案」
- **凭据：无**。这张表里只有地址、网卡名和度量，不读配置文件、不碰任何密钥
- ★ 测试**不发一个包、也不读真机的表**：全表、问系统、是不是本机地址、解析这四个读取口都是变量，
  所以「两条默认路由」「算的和给的不一样」「并列几条」这些档在挂着 VPN 的机器上和干净机器上
  跑出来一模一样（否则 CI 会红在跟本次改动无关的那一行上）。
  专门钉了一条「给的是 IP 时一个 DNS 都不问」；另有一组测试把各平台命令输出的**纯解析**
  全跑一遍（解析函数不带 build tag），所以 Windows 那套解析在 macOS 上也被测到了
- ★ **对不上的一句账**：这一个加进去之后注册表里是 **49 个**工具（之前 48 个），
  而上面几条写的「工具从 36 个到 37 个」那个数**从来不是注册表数** —— 它是最早按诊断类工具数的，
  后来加远程、媒体、DHCP 那几批时没跟着改。发布说明里这句要么整行删掉，要么统一改成注册表数，
  ★ 别照旧写：客户拿这个数对不上，就会开始怀疑其余每一条

# 技术说明
feat(tools,ui): net.fileshare.serve / .status / .stop —— 把本机一个目录开成只读的固件下载地址

- 现场用途很窄：**设备的升级页面要填一个 `http://…/xxx.bin`**，交换机要把配置文件拉回去。
  以前这一步要么翻 U 盘、要么临时装一个第三方小服务 —— 而那些服务**默认能写、默认绑
  0.0.0.0、默认把整个盘端出来**，装完就没人管了。这里只做三件事：只读、只绑按网卡算出来的
  那几个地址、只开指定的那一个目录
- ★★ **写路径在这个包里不存在，不是「鉴权后允许写」**：HTTP 只接 GET/HEAD，其余方法当场 405
  并且**记一笔被拒**。`internal/filesrv` 里没有 PUT/POST 的分支 —— 一个功能是「没实现」还是
  「结构上实现不了」，隔了很久就会变味，所以从代码形状上就没有
- **不绑 0.0.0.0，一个地址一个监听器**：多网卡工控机上那块口可能正连办公网甚至公网。
  地址由工具层按网卡现算（`shareAddrs`：v4 在前、ULA/全局 v6 在后，**链路本地不给** ——
  设备不会照着 `fe80::…%en0` 去填地址），这里只负责绑
- ★ **多个监听器必须共用同一个端口号**：填 0 让系统挑时，第一块网卡拿到真实端口后要写回
  `s.cfg.Port`，后面几块绑同一个号。不写回的后果很隐蔽 —— 界面只给一条 URL 列表，
  换块网卡下载就失败，而人完全看不出为什么
- **一次只允许一个共享**：两个共享要让人分清「停的是哪个」，这件事在现场一定出错
- **`/` 不接受当共享根**、**符号链接两道检查**：`filepath.Join` 自己会吃掉 `../`，
  只看拼接后的字符串永远看不出问题；真正危险的是根目录里有一层**符号链接**指向别处
  （现场太常见 —— 有人把某个目录软过来当固件目录）。所以先逐段 `Lstat` 拒绝任何一层链接，
  再用 `EvalSymlinks` 复核落点确实在根里。★ `inside()` 补分隔符再比：
  `/firmware` 是 `/firmware-secret` 的前缀，光 `HasPrefix` 会把隔壁那个目录也算成「在根里」
- ★★ **mutate + 每次点头，而且批准说明要说到人能拍板**：这张卡改的不是本机配置，
  是**这台机器对外的可见面** —— 一开就是「同一网段任何设备不必登录把这个目录整个读走」。
  最坏情况是忘关（把整个用户目录端出来开一下午这种事在别的工具里出过）。
  所以批准句里必须写明：哪个目录、开在哪块网卡（**当场算出来的那块名字**，不是「自动选」）、
  绑哪些地址、只读、以及目录里**看着像密钥的文件名**
- ★ **密钥提醒必须出现在批准说明里，不能只写在结果里**：只看文件名判断（`.key/.pem/id_rsa/.env/…`），
  **永不读内容**。点批准的人要是只看到「共享一个固件目录」，他实际放行的是
  「把这台机器的密钥挂到网上」。这一条是被测试逼出来的：先只写进了结果，批准句里没有，等于没有
- **169.254 不能当共享地址**、**没有账本就不许开**、**参数错误先于账本检查**：
  后两条顺序反了的话，一个填错目录的调用会报「没有改动账本」，人就跑去查配置了
- **台账按笔记，状态分七种**：`ok` 整份取走 / `head` 只问了大小 / `range` 按段取（断点续传在跑，
  不是失败）/ `partial` 说好了整份、中途断了（★ 现场要的就是这一笔）/ `list` 翻了目录 /
  `denied` 想上传或想翻出目录 / `not-found` 文件名没对上
  - ★ `countWriter` **故意不实现 `ReadFrom`**：实现了 `http.ServeContent` 就走 splice，那一步数不到，
    现场就会出现「传完了但记账是 0」
  - ★★ **`denied` 和 `not-found` 必须是两个数**。合成一个「失败 N 次」的话，
    文件名抄错（现场常态）会把「有人在拿它试上传」（必须让人看见的那类）淹掉，
    还会让一个干净的共享看着像被攻击过
- **停是当场断**：`Stop()` 用 `http.Server.Close()` 不用 `Shutdown()` —— 固件传到一半不用等它传完。
  界面上「立刻停掉」旁边没有进度条，这一下就是把正在传的那一发也立刻掐掉
- **账怎么记**：这里的「改动」是本机在监听端口，进程一退端口就空了，**没有状态要还原**。
  开着时那笔挂 `applied`（在账上看得见），停掉翻篇；重启时 `restoreFileShare` 把上次没停的
  那种账了结并写日志，★ **绝不自动重开** —— 那等于人不在场就把一个目录开到网上去
- ★ **`status` 要带全界面上不该消失的字段**（`port`、`listing`、网卡和它怎么挑的、目录规模、密钥提醒）：
  台账每 3 秒自己刷一次，第一次是 serve 的形状、之后是 status 的形状，
  少一个字段就是**刷一次少一行**。踩过两次：先是端口和「能不能翻目录」没了，
  然后是「开在哪块网卡、这块口是怎么挑中的」和那句 `id_rsa 还挂着` 只活三秒 ——
  而这些正是人决定「要不要现在停掉」的依据。测试里钉了一条「状态刷新不丢开共享时那几行」
- **目录页标题被符号链接坑过一次**：`resolve` 交回的是链接后的真身，根却拿没解开的比，
  macOS 上 `/tmp` → `/private/tmp`，根目录那一页就成了 `../../private/tmp/…`，
  人看一眼以为共享开错了目录。改成启动时算好 `rootReal`，比的人和看的人是同一个值
- **注册表级测试是被自己咬出来的**：schema 里串进了一段 Go 的字符串拼接（写在反引号里，
  编译过、其它测试全绿），一直到起服务时才炸。现在有一条测试把整张注册表里每一项的
  schema 都过一遍 JSON 校验、并检查 `additionalProperties: false`
- ★ 测试**不依赖真网卡、也不看这台机器的默认路由**：读网卡、读默认路由、本机地址这三个口都是变量，
  所以「两块网卡时不许猜」「只有一块才自动选」「默认路由那块优先」这些档，
  挂着 VPN 的机器和干净机器跑出来一模一样。端到端那几条只在 `127.0.0.1` 上起真监听器
- 真机实测：默认路由那块口开一次一秒、设备地址取文件 200、HEAD 只记大小、POST 405 且没写出任何文件、
  穿越路径取不到根外的东西、台账七种状态各来一笔、停掉后端口立刻空、账本 applied→reverted、
  重启时上次没停的账自己翻篇且不重开
- 注册表现在 **52 个工具**（`netkitd` 启动日志里的数，界面上那个数以它为准）

# 技术说明
feat(tools,filesrv,ui): 文件共享连 TFTP 一起开 —— 老设备的升级页面只认 tftp://

- 补的是上一张卡留下的一个真实缺口：**有一批设备的固件页面只认 `tftp://`**，
  地址栏填 http 它一律报「下载失败」，而现场没人会怀疑是协议不对 ——
  所以这一个共享要能多开一个 UDP 口，而不是只给 http
- ★★ **这个文件里没有写路径**：TFTP 只处理 RRQ，收到 WRQ 当场回 ERROR(2) 并单独记一笔 `denied`。
  TFTP 的 WRQ 比 HTTP 的 PUT 更危险 —— 连文件名都是对端给的。
  别的实现里「不收文件的 TFTP」经常只是「没人去点那个开关」，这里是**没得点**
- 几处必须照规范来的地方，做错的表现全都是「有的设备上能用、有的永远卡住」，这一类最难查：
  - **每笔传输换一个源端口**（[RFC 1350] 的 TID）。不换的话客户端只在自己那个随机端口上等回话，
    我们从监听口发出去的东西它不认 —— **拿 netcat 手测永远正常，接上真实设备卡在第一包**
  - **每一发都要连数据一起重发**。丢一个 ACK 是常态不是异常（固件几十 MB、交换机管理口那点 UDP 缓冲）；
    只重等不发的那种写法，症状是「传到一半停了」，而现场只会以为网不好。
    1 秒起指数退避、共 5 次（约 31 秒）：太密正打在交换机那点缓冲上，太慢会撞设备的下载超时（多数 30 秒）
  - **块号 65535 之后回绕到 0**。只在文件和 blksize 足够大时才碰到（512 字节要 32MB，
    blksize=1456 时约 90MB）—— 也就是说它**从来不在随手写的测试样本里**，所以单独钉一条测试
    （用 blksize=16 把回绕压进几秒内，并且不许在循环里自己加「回绕判断」）
  - **OACK 只回自己认得的选项**（blksize / tsize / timeout），顺序跟对端提的一致。
    把对端提的选项原样抄回去等于答应了我们没实现的事（比如按它要的秒数重传 —— 直接不回那一项）。
    `tsize` 报**真实大小**：设备的升级页面靠这个数判断取完没有，报 0 会让它「传完了还以为没传完」然后反复重下
  - 对端提的 blksize 每步都按边界查（16 到 64508，再大单个 UDP 包就得 IP 分片，现场等于自杀）；
    RRQ 尾巴上多带一个 0 的**丢掉不报错** —— 现场有一批实现这么发包，为这个拒掉设备没有意义
- ★★ **顺手修掉一个真实的对外泄漏**：绑定 TFTP 时原本用 `net.ParseIP` 解地址，而它
  **对带区的地址（`fe80::1%en0`，交换机管理口常用）返回 nil**，nil 传给 `ListenUDP` 的意思是
  「**绑所有网卡**」 —— 一个「只开管理口」的只读共享就这么从机器上其余每一块口也开出去了。
  改成 `net.ResolveUDPAddr`，解不开就当场失败并说「这个地址本机没有」
- **一笔一个地址族，并且绑监听口那个地址**：双栈机器上默认口发 v6 单播会失败，
  症状是「IPv6 的设备取不到」而 v4 一切正常；从别的网卡回话会被按源地址过滤的设备丢掉
- **限制同时在传的笔数（32）**：这是一个**不鉴权**的服务，同网段谁都能开一笔，
  不设上限的话谁写个循环，这台机器的 goroutine 和 socket 就上去了。到上限回 ERROR(4) 并记 `busy`
- ★ 状态口径和 HTTP 那侧对齐，并且**多两种**：协商那一步就没回话单独记 `aborted`
  （多半是那台设备**不支持选项协商**却又提了选项 —— 该查的是它的 TFTP 实现，不是网），
  不和「传到一半断了」的 `partial` 混，因为该做的下一步完全不同。
  设备按 `netascii` 来要时**照原样字节发**（真去转行尾就是把设备刷坏），
  单独记 `octet-served`，让人看得见「是它按 netascii 来要的」而不是我们悄悄替它决定
- ★ **`denied` 和 `not-found` 继续是两个数**：越出共享目录（含符号链接那两道检查）算被拒，
  文件名对不上算没找到。前者是「有人在拿这个口试」，后者是现场常态，合成一个数就两个都看不见了
- Windows 那侧的设备会传带反斜杠的文件名，也有设备不带头顶的斜杠：不先归一的话它们全都
  「没有这个文件」，而人只会以为是共享没开对
- 1024 以下起不来时的话**按协议分开**：TFTP 这一句要单独说清楚 —— 设备的固件页面经常写死 69，
  所以要么换个端口（设备上那一栏允许改的话），要么以更高权限起
- 测试：手写一个 TFTP 客户端跑端到端（不拿第三方库测自己），逐条钉住上面这些规范细节；
  ★ 另外用系统自带的 `/usr/bin/tftp` 做**独立实现互测**：4 MB 取下来逐字节相同、
  `put` 被拒且本机没多出任何文件、取不存在的东西报「没有」、台账 ok / denied / not-found 分开且都带 `proto:"tftp"`
- ★ 工具数不变（还是 52 个）：这一笔是给已经跑着的那三个工具多开一个协议。
  `serve` 和 `status` 的结果里都带 `protocols` / `tftpPort` / `tftpUrls`，
  界面上台账每 3 秒自刷一次也不丢行 —— 「开在哪两个口上」正是人决定要不要停掉的依据

# 用户更新说明
## 新增
- **「文件共享（只读）」现在可以连 TFTP 一起开**：有一批老设备的升级页面只认 `tftp://`，
  填 http 地址一律「下载失败」—— 勾上那一项就多开一个 UDP 口，不用再去找一台老服务器
- ★ **默认不勾**：只需要 http 的时候不给你多开一个对外端口；老设备取完固件记得把它关掉
- ★ **一样只读，而且这次是物理上的只读**：它只发不收，设备传不上来任何东西，
  本机的文件也改不了删不了；有人拿这个口试上传，会单独记一笔给你看
- ★ **开 TFTP 也要你点一次头**：批准那句话里写清了这次是两个端口（http 一个、UDP 一个）、
  开在哪块网卡、绑哪些地址 —— 一样绝不绑「对外开放的所有地址」
- **大固件、慢链路那种「传到一半不动了」现在会自己重传**，不再一句话甩给「网不好」；
  块大小按设备提的来（太离谱的会拒绝并说清可用范围）
- **设备取不到东西时看得见断在哪一步**：有没有来取过、取到第几字节停的、
  是那台设备不支持协商、还是文件名根本没对上 —— 这些以前只能靠猜
- ★ **文件名抄错和想上传是两笔账**：填错固件名是现场常态，不会被算成「有人在试这个共享」；
  真想上传的那几次也不会被你抄错的那几次盖住
- 端口 69 起不来时会直说是为什么，并且给两条路（换端口 / 更高权限），不让你去查防火墙

# 技术说明
feat(tools,filesrv,ui): 文件共享连 FTP 一起开 —— 另一批设备和交换机只认 ftp://

- 上一笔补了 tftp，这一笔补的是同一类缺口的另一半：**交换机的配置文件、另一批 IPC 和老设备的
  固件栏只认 `ftp://`**（填 http 它连试都不试）。同一个目录、同一套只读规则，多开一种协议，
  而不是让现场再架一台服务器
- ★★ **写命令在这个文件里压根不存在**：`STOR`/`APPE`/`DELE`/`MKD`/`RMD`/`RNFR`/`RNTO`/`SITE`
  一律 550 并且**单独记一笔 `denied`**。FTP 的 `STOR` 连文件名带路径都是对端给的，
  能写就等于这个目录可写 —— 所以这里不是「界面上没给上传按钮」，是没有那条代码路径
- ★ **`PORT`（主动模式）只允许连回「把它连进来的那个地址」**。PORT 的语义是本机**主动出站**
  去连对端报上来的 ip:port，不校验的话这台机器就成了一个现成的内网探针：
  谁都能借它挨个试「内网哪个地址哪个端口连得上」，而且日志上看着是我们发起的。
  拒的那一笔同样进台账（写的是 `PORT→ip:port（不是连进来的那个地址）`），因为这件事本身要看得见
- ★ **PASV 的数据口必须绑在控制连接那一侧的地址上**，不能图省事绑通配。
  绑通配的话：设备从管理口连进来，我们却把数据口从办公口甚至公网口也开出去了，
  而且**一声不响** —— 界面上写着「只绑了这块网卡」。测试里直接拿另一块本机地址去连那个口，连上就是失败
- **数据口一笔换一个**（每次传输新开、传完就关）：复用同一个口，第二个文件的 LIST 和 RETR
  会互相串，症状是「列完目录之后取不到东西」，而这类现象在真实设备上出现得太随机，没人会怀疑到实现上
- **超时按「每一发」算，不给整笔传输设总时限**：固件几十 MB、慢链路就是能取十几分钟。
  写成总时限的话，表现成「小文件都正常，大固件一律下到一半断」，
  而现场只会去怀疑设备和网。控制连接的空闲（2 分钟）和数据连接的每一读一写分开计
- **`ASCII` 模式照原样字节发**，并且记 `octet-served`：固件是二进制的，真去转行尾就是把设备刷坏。
  单独记这一笔是为了让人看得见「是它自己按 netascii 来要的」，而不是我们悄悄替它做了决定
- **同时最多 16 条会话**，超了回 421 并记 `busy`：这是一个**不鉴权**的服务，
  同网段谁都能开一条挂着不走，不设上限就是拿 goroutine 和 socket 堆死这台机器
- `FEAT` 只报真做了的命令，并且有一条测试反过来验：报出来的每一个命令都要能在会话里走通 ——
  抄一份别家的 FEAT 列表，设备会去用我们没实现的命令，症状是「有的设备好使、有的一脸懵」
- 台账状态和 http / tftp 两侧对齐：`ok` / `head`（只问了 `SIZE`）/ `list` / `not-found` /
  `denied` / `partial` / `busy` / `octet-served`。`SIZE`、`MDTM`、`MLST`、`MLSD` 都记账，
  因为设备「升级前先看一眼多大」这一笔在现场就是它来过的证据
- **密码不落任何地方**：`USER`/`PASS` 只为走完握手（这是个不鉴权的只读共享，回的是
  「随手填一个就行」）。有一条测试把 `Status` 整个 JSON 序列化出来找那两个字符串，
  出现即失败 —— 结果是要发给 AI 的，凭据进去一次就等于贴出去了
- ★ 顺手修掉一个**三个协议一起中招**的containment 误伤：判「越出共享目录」用的是
  `HasPrefix(rel, "..")`，于是真叫 `..草稿.bin`、`..IPCamera_full_V2.4.5.bin.part` 这类文件
  （下载中断、隐藏文件、某些工具的临时名，现场都有）会被当成越界拒掉，
  而报的那句是「这个路径不在共享目录里」—— 没人想得起来是文件名的锅。
  改成带上分隔符再比，并且钉一条 HTTP 测试
- ★ 工具数不变（还是 52 个）：这一笔是给已经跑着的那三个工具多开一种协议。
  `serve` / `status` 的结果里都带 `protocols`（现在三种一起列）/ `ftpPort` / `ftpUrls`，
  批准那句话要把**三个口**都念出来，停掉那句要逐个说清哪几个口放掉了 ——
  「以为停了、其实 ftp 那个口还在收」是这类功能最坏的一种收尾
- 另外修了一个界面样式上的老问题：`input { width: 100% }` 把复选框也拉成一整条，
  一行里放两个以上勾选项时，框会压到隔壁那条的文字上（看着像文字里嵌了个框）。
  复选/单选框改成不吃这条宽度 —— 这一条不只影响这张卡

  勾上那一项，同一个目录就能用 ftp 地址取 —— 不用再单找一台服务器

- ★ **一样只读，而且是物理上的只读**：上传、删除、改名、建目录这些命令它压根不认，
  本机任何东西都改不了；有人拿这个口试写，会单独记一笔给你看
- ★ **开 FTP 也要你点一次头**：批准那句话里把三个口都念出来（http、UDP 的 tftp、ftp），
  并且写清 FTP 每传一个文件还要临时开一个数据口 —— 你点头的是完整的那一件事，不是「开共享」三个字
- **隔着一层防火墙也知道该放行什么**：FTP 除了控制口还要数据口，
  只放行 21 的表现是「登录得上、列得出目录、就是取不到文件」，界面上直接把这句话说给你，不用去猜
- **主动模式的设备连不上时报得清楚**：我们只允许它连回自己连进来的那个地址（这是安全边界，
  不让这台机器被别人借去探内网），需要走主动模式又隔着 NAT 的设备，让它改成被动模式（PASV）
- **停共享的时候看得见三个口是不是都放了**：停掉那句逐个列出放掉了哪几个端口，
  正在传的那一发当场断，不留「界面上说停了、其实还在收」的口子
